# 价格区间预测系统设计方案

## 1. 设计背景

### 1.1 问题描述

模拟交易的仓位构建需要"预测下一根 bar 的价格范围"来决定挂单位置。当前系统（judgment.py Rule 5）用一个简单的"无信号+盈利+未满仓->加仓"逻辑，既没有价格层级概念，也不够准确。经确认该逻辑为 bug，需要重新设计。

### 1.2 设计目标

- 预测引擎是**系统级共享服务**，与具体策略 DNA 解耦
- 公式结构由**独立的离线进化**发现，进化产出后固定
- 在线阶段通过 GARCH 状态递推实现自迭代（公式不变，状态更新）
- 预测准确率超过 50%，覆盖 BTC/ETH 的多种市场状态
- 每根 bar 只需记住约 15 个数值，不需要保留历史 K 线数据

### 1.3 核心原理

预测的本质是**波动率预测**，不是价格方向预测。波动率具有持续性和均值回归性（Engle, 1982; GARCH 模型），在 BTC 上这个特性尤其强烈。ATR * 0.5 作为单侧区间就能达到 60-70% 的覆盖率，通过 GARCH 递推 + 因子调整可进一步提升。

## 4. 核心接口设计

### 4.1 PredictionDNA -- 公式基因

```python
@dataclass
class PredictionDNA:
    """预测公式的基因表示。进化产出后序列化为 JSON 持久存储。"""

    # GARCH(1,1) 参数
    omega: float                    # 长期方差基准 (1e-6 ~ 1e-3)
    alpha: float                    # 冲击敏感度 (0.01 ~ 0.30)
    beta: float                     # 方差持续性 (0.70 ~ 0.98)

    # 宽度乘数
    k_base: float                   # 基准乘数 (0.3 ~ 1.2)
    k_min: float                    # 安全下限 (0.2 ~ 0.5)

    # 因子权重（8 个因子，权重为 0 表示不使用）
    factor_weights: Dict[str, float]

    # 张力计算窗口
    short_window: int               # 短周期窗口 (5 ~ 30)
    mid_window: int                 # 中周期窗口 (30 ~ 100)
    long_window: int                # 长周期窗口 (100 ~ 300)

    # 元数据
    prediction_id: str = field(default_factory=lambda: str(uuid.uuid4()))
    generation: int = 0
    fitness_score: float = 0.0

    # GARCH 平稳性约束
    @property
    def is_stationary(self) -> bool
        """GARCH(1,1) 平稳性要求 alpha + beta < 1。"""

    def clamp_params(self) -> None
        """变异后强制约束 alpha + beta < 0.95（留安全余量）。
        若超限，按比例缩减 alpha 和 beta 使其满足约束。"""

    # 序列化
    def to_dict(self) -> dict
    @classmethod
    def from_dict(cls, data: dict) -> PredictionDNA
    def to_json(self) -> str
    @classmethod
    def from_json(cls, json_str: str) -> PredictionDNA
```

**因子池定义**（固定 8 个因子，进化只搜索权重）：

| 因子名 | 含义 | 数学定义 |
|--------|------|----------|
| `vol_regime` | 波动率状态 | `ATR / SMA(ATR, 50)` |
| `bb_squeeze` | 布林带收窄程度 | `1 - BB_width 百分位排名` |
| `rvol` | 相对成交量 | `Volume / SMA(Volume, 20)` |
| `tension_short` | 短周期价格张力 | `abs(z-score, short_window)` |
| `tension_mid` | 中周期价格张力 | `abs(z-score, mid_window)` |
| `tension_long` | 长周期价格张力 | `abs(z-score, long_window)` |
| `tension_divergence` | 短长张力背离 | `abs(tau_short) - abs(tau_long)` |
| `adx_strength` | 趋势强度 | `ADX / 100` |

### 4.2 PriceRangePredictor -- 预测器

```python
class PriceRangePredictor:
    """系统级共享的价格区间预测器。"""

    def __init__(self, dna: PredictionDNA)

    # 生命周期
    def warmup(self, df: pd.DataFrame, n_bars: int = 100)
        """用历史数据预热 GARCH 状态。调用 predict 前必须先 warmup。"""

    # 核心接口
    def predict(self, df: pd.DataFrame, idx: int) -> PredictionResult
        """基于当前 GARCH 状态和因子，预测下一根 bar 的价格区间。"""

    def observe(self, actual_high: float, actual_low: float,
                predicted: PredictionResult) -> None
        """观察实际结果，更新 GARCH 状态。每根 bar 结束后调用一次。
        必须在 predict 之前调用（先更新 GARCH 状态）。"""

    # 状态管理
    def state_dict(self) -> dict
        """导出运行时状态（GarchState + 命中统计），供可选持久化。"""

    def restore_state(self, state: dict) -> None
        """从 dict 恢复运行时状态。"""

    # 状态查询
    @property
    def hit_rate(self) -> float
    def needs_retrain(self) -> bool
```

**调用方的使用模式**（固定的三步循环）：

```python
# 初始化一次
predictor = PriceRangePredictor(dna)
predictor.warmup(df)

# 每根 bar
prediction = predictor.predict(df, i)       # 预测下一根
# ... 等下一根 bar 走完 ...
predictor.observe(actual_high, actual_low, prediction)  # 更新状态
```

### 4.3 PredictionResult -- 输出

```python
@dataclass
class PredictionResult:
    low: float          # 预测区间下界
    high: float         # 预测区间上界
    width: float        # 单侧半宽 = sigma * K（high - low = 2 * width）
    k_actual: float     # 实际使用的动态 K 值
```

### 4.4 GarchState -- GARCH 状态

```python
@dataclass
class GarchState:
    """GARCH(1,1) 在线递推状态。只需记住 2 个数值。"""
    sigma_sq: float = 0.0   # 当前方差估计
    epsilon: float = 0.0    # 上一期冲击

    def update(self, actual_range: float,
               omega: float, alpha: float, beta: float) -> float
        """用当前 bar 的实际 range 更新状态，返回新的 sigma。"""
        # epsilon = 实际 range - 上一期预测的 sigma
        # sigma_sq = omega + alpha * epsilon^2 + beta * sigma_sq

    @classmethod
    def init_from_history(cls, ranges: pd.Series,
                          omega: float, alpha: float,
                          beta: float) -> GarchState
        """用历史 range 序列预热初始化。"""
```

### 4.5 PredictionEvolver -- 离线进化器

```python
class PredictionEvolver:
    """离线进化预测公式。不在交易运行时使用。"""

    def __init__(self, df: pd.DataFrame,
                 population_size: int = 60,
                 max_generations: int = 50)

    def evolve(self) -> PredictionDNA
        """执行进化，返回最优 PredictionDNA。"""
```

**调用方使用方式**：

```python
df = load_historical_data("BTCUSDT", "4h")
df = compute_all_indicators(df)

evolver = PredictionEvolver(df)
best_dna = evolver.evolve()

# 持久化

```

## 5. 内部计算流程

### 5.1 predict(df, idx) 执行路径

```
    close = df["close"].iloc[idx]
    sigma = sqrt(garch_state.sigma_sq)

    factors = compute_factors(df, idx, dna)
        |
        +- vol_regime      = atr_14 / sma(atr_14, 50)
        +- bb_squeeze      = 1 - rank(bb_width)
        +- rvol            = volume / sma(volume, 20)
        +- tension_short   = abs((close - sma_short) / std_short)
        +- tension_mid     = abs((close - sma_mid) / std_mid)
        +- tension_long    = abs((close - sma_long) / std_long)
        +- tension_diverge = tension_short - tension_long
        +- adx_strength    = adx_14 / 100

    K = k_base + sum(weight_i * factor_i)
    K = max(K, k_min * emergency_mult)

    width = sigma * K
    return PredictionResult(low=close-width, high=close+width, ...)
```

### 5.2 observe(actual_high, actual_low, predicted) 执行路径

```
    actual_range = actual_high - actual_low
    garch_state.update(actual_range, omega, alpha, beta)
        |
        |  sigma_sq = omega + alpha * epsilon^2 + beta * sigma_sq
        |
    更新 hit_count / miss_streak
```

### 5.3 不做方向预测

中心固定为当前 close，所有建模能力集中在宽度 W 上。理由：
- 方向信噪比极低（弱式有效市场假说）
- 均值回归假设在趋势行情中系统性错误
- 对仓位构建挂单的用途，对称区间已完全足够

### 5.4 与 runner.py 主循环的集成时序

predict/observe/tranche 必须精确嵌入 runner.py:367-400 的 bar 处理序列。
以下定义每根 bar[i] 的完整执行顺序：

```
初始化（主循环开始前）：
    predictor.warmup(df)
    current_prediction = predictor.predict(df, len(df) - 1)  # 预测第一根新 bar
    current_plan = None

每根 bar[i]（runner.py for i in range(len(df), len(new_df))）：

  Step 1: 执行 pending_decision（来自 bar[i-1] 的 evaluate）
    events, deferred = account.process_bar_v2(
        bar_high, bar_low, bar_open, bar_close, bar_time,
        pending_decision=pending_decision,
        position_plan=current_plan,              # 挂单计划
        prediction_result=current_prediction,    # 对 bar[i] 的预测
    )
    内部：SL/TP → 强平 → 执行 Decision → _process_tranches → 资金费率 → 快照

  Step 2: observe bar[i] 的实际结果，更新 GARCH 状态
    if current_prediction is not None:
        predictor.observe(bar_high, bar_low, current_prediction)

  Step 3: 预测 bar[i+1] 的区间
    current_prediction = predictor.predict(new_df, i)

  Step 4: 管理 PositionPlan 生命周期
    for evt in events:
        if evt.action == "open":
            # 开仓成功 → 创建 PositionPlan（第 1 笔已市价执行，创建第 2、3 笔挂单）
            current_plan = PositionPlan.from_prediction(
                prediction=current_prediction,
                target_pct=state.target_position_pct,
                side=account.position.side,
                entry_price=account.position.entry_price,
                stop_loss=account._stop_loss,
            )
        elif evt.action in ("close", "liquidation"):
            # 平仓 → 清除计划
            current_plan = None

  Step 5: 现有评估逻辑（不变）
    if deferred is not None:
        pending_decision = deferred
        continue
    signals = BarSignals.from_signal_set(sig_set, i)
    state = account.get_state(close)
    decision = evaluate(signals, state, config)
    if decision.action != "hold":
        pending_decision = decision
```

时序关键约束：
- current_prediction 在 bar[i-1] 的 Step 3 生成，在 bar[i] 的 Step 1 使用
- observe 必须在 predict 之前调用（先更新 GARCH 状态，再生成新预测）
- PositionPlan 创建在 Step 4（开仓事件检测），而不是在 API 路由中

### 5.5 恢复路径（_min_replay）的 predictor 集成

runner.py 的 _min_replay() 在任务恢复时重放历史 bar。predictor 必须在此路径中
同步调用 observe，确保 GARCH 状态在重放结束后与正常运行一致。

```
_min_replay(account, sig_set, df, start_idx, ..., predictor=None):
    current_prediction = None
    if predictor is not None and start_idx > 0:
        current_prediction = predictor.predict(df, start_idx - 1)

    for i in range(start_idx, len(df)):
        # 现有 process_bar_v2 + evaluate 逻辑不变
        events, deferred = account.process_bar_v2(...)

        # predictor 集成
        if predictor is not None:
            if current_prediction is not None:
                predictor.observe(high[i], low[i], current_prediction)
            current_prediction = predictor.predict(df, i)
```

注意：恢复路径中不创建 PositionPlan（重放期间不执行实际挂单），
只更新 GARCH 状态确保 predict 的 sigma 准确。

## 6. 应急机制

```
连续 miss 0~2 根 bar: k_min 不变
连续 miss 3~4 根 bar: k_min * 1.5
连续 miss 5+ 根 bar:  k_min * 2.0
命中 1 根 bar:        miss_streak 归零，k_min 恢复

命中率持续低于 45%（50 根 bar 窗口）:
    needs_retrain = True
    标记需要离线重新进化
```

这不是修改公式，而是在公式的安全边界（k_min）上做应急调整。公式结构不变，只是下限被临时抬高。

## 7. 适应度函数

进化器的评分标准：

```
对每个 bar:
    如果 实际 [low, high] 在预测范围内:
        score = 实际宽度 / 预测宽度      <- 命中且紧凑，越接近 1 越好
    如果 超出预测范围:
        score = -(超出量 / 实际宽度)     <- 惩罚，超出越多扣越多

fitness = mean(score) * 0.6 + hit_rate * 0.4
```

60% 权重给紧凑度，40% 给命中率。进化会自动找到覆盖率 vs 紧凑度的最优平衡。

## 8. 进化搜索空间

| 参数 | 搜索范围 | 说明 |
|------|---------|------|
| omega | 1e-6 ~ 1e-3 | GARCH 长期方差 |
| alpha | 0.01 ~ 0.30 | 冲击敏感度 |
| beta | 0.70 ~ 0.98 | 方差持续性 |
| k_base | 0.3 ~ 1.2 | 基准乘数 |
| k_min | 0.2 ~ 0.5 | 安全下限 |
| factor_weights[8] | -1.0 ~ 1.0 | 各因子权重 |
| short_window | 5 ~ 30 | 短周期窗口 |
| mid_window | 30 ~ 100 | 中周期窗口 |
| long_window | 100 ~ 300 | 长周期窗口 |

变异操作：
- 高斯扰动连续参数
- 随机置零/恢复因子权重（因子选择）
- 调整窗口参数
- 交叉：混合两个父代的参数
- **变异后必须调用 `dna.clamp_params()` 强制 alpha + beta < 0.95**

硬约束：
- `alpha + beta < 0.95`：GARCH(1,1) 平稳性要求。超过 1 会导致方差爆炸（sigma_sq → ∞）
  现有进化引擎（core/strategy/validator.py）只支持单参数范围检查，不支持跨参数约束。
  PredictionDNA 通过自身的 `clamp_params()` 方法在变异后强制修正

## 9. PositionPlan 仓位构建设计

### 9.1 数据结构

```python
@dataclass
class Tranche:
    """单笔挂单计划。"""
    price_level: float         # 挂单目标价
    size_pct: float            # 占 equity 的比例
    status: str = "pending"    # "pending" | "filled" | "cancelled"
    bars_waiting: int = 0      # 已等待 bar 数

@dataclass
class PositionPlan:
    """仓位构建计划。"""
    tranches: List[Tranche]
    target_pct: float          # 总目标仓位
    max_wait_bars: int = 5     # 单笔最长等待
    max_chase_pct: float = 0.5 # 最高追价比例（相对 stop_loss）
```

### 9.2 挂单策略

开仓后创建计划，目标仓位拆为 3 笔：

| 笔数 | 触发方式 | 价格 | 占比 |
|------|---------|------|------|
| 第 1 笔 | 信号触发时立即执行（现有 Rule 2） | bar_open | 33% |
| 第 2 笔 | 挂单 | `predicted_low + width * 0.2` | 33% |
| 第 3 笔 | 挂单 | `predicted_low` | 34% |

### 9.3 追价逻辑

- 每 bar 用新预测更新第 2、3 笔的挂单价（做多时只升不降）
- 单笔等待超过 max_wait_bars (5) 后进入追价模式
- 追价上限 = `entry_price * (1 + stop_loss * max_chase_pct)`
- 超过追价上限的 tranche 取消，接受不满仓

| 评分管线 | `core/scoring/` | normalize + weighted sum 模式 |
| `process_bar_v2` 的流程 | `core/trading/account.py` | PositionPlan 作为新步骤插入 |

---

## 13. 关键设计决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 中心预测 | 不做方向预测，用当前 close | 方向信噪比极低，引入方向偏移会系统性错误 |
| 宽度预测 | GARCH 递推 + 因子加权 | GARCH 有理论基础，因子加权表达力够且可进化 |
| 因子选择 | 进化决定，人为只定义池 | 避免主观偏见，让数据说话 |
| 在线自迭代 | GARCH 状态递推（公式不变） | 数学严谨，不像梯度下降会追噪声 |
| 追价机制 | 每 bar 用新预测更新挂单价，只升不降 | 保证不超过 max_chase 上限 |
| Rule 5 处理 | 删除 | 被 PositionPlan 完全替代 |
| 应急机制 | 连续 miss 时抬高 k_min | 不改公式，只调整安全边界 |
| GARCH 稳定性 | clamp_params() 强制 alpha + beta < 0.95 | 防止方差爆炸（sigma_sq → ∞），现有 validator 不支持跨参数约束 |
| PositionPlan 创建 | runner.py 检测开仓事件后创建 | api/routes/trading.py 只创建 DB 任务，不参与交易执行 |
| 进化引擎 | PredictionEvolver 独立实现 | 现有 EvolutionEngine 深度耦合 StrategyDNA，无法复用 |
