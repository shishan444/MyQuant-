# 评分系统重构需求

## 背景

当前自动探索（进化）系统的评分机制存在结构性问题，导致进化搜索方向与"收益优先、稳定其次"的设计原则相悖。具体表现：高收益策略因回撤被过度惩罚而被淘汰，收益梯度过平导致搜索信号弱，11个评分维度高度相关导致权重形同虚设。

## 需求列表

---

### 需求1：修复回撤三重惩罚（P0 - 结构性Bug）

**问题**：max_drawdown 在三个层级被重复惩罚：
1. 归一化层：dd > 20% 触发平方惩罚（normalizer.py:37-38）
2. 维度加权层：作为维度参与加权求和（templates.py 各模板 10-25% 权重）
3. 全局惩罚层：dd >= 50% 再次施加梯度惩罚（scorer.py:74-80）

**结果**：一个年化200%、回撤35%的优秀策略，回撤维度在到达最终分数前被惩罚两次，对总分的影响约为设计预期的3倍。

**修复要求**：
- 去掉归一化层的平方惩罚（normalizer.py:37-38），max_drawdown 改为纯线性归一化：`score = (1.0 + value) * 100`，0%=100分，100%=0分
- 去掉全局惩罚层（scorer.py:74-80），删除 `_DRAWDOWN_PENALTY_THRESHOLD` 和 `_DRAWDOWN_FATAL` 相关逻辑
- 回撤只通过维度加权方式参与评分，由模板权重控制其影响力

**涉及文件**：
- `core/scoring/normalizer.py` - 修改 max_drawdown 归一化逻辑
- `core/scoring/scorer.py` - 删除全局回撤惩罚代码

**验证标准**：
- 年化200%、回撤35%的策略，其 max_drawdown 维度归一化分数应为 65（而非当前的 42.25）
- 全量测试通过，无回归

---

### 需求2：修复 annual_return 归一化梯度过平（P0 - 结构性Bug）

**问题**：当前使用 log 映射，0%（不赚钱）→ 38.9分，100%（翻倍）→ 61.1分，差距仅22分。进化算法难以区分"不赚钱"和"翻倍"的策略差异，搜索信号弱。

**修复要求**：
- 将 log 映射改为分段线性映射，在核心区间（0%-100%）提供更陡的梯度：

```
[-100%, 0%]  → [0, 30]     亏损区间，快速归零
[0%, 100%]   → [30, 70]    核心区间，梯度陡峭（40分区间 vs 当前22分）
[100%, 500%] → [70, 100]   高收益区间，缓慢增长
```

**涉及文件**：
- `core/scoring/normalizer.py` - 重写 annual_return 分支

**验证标准**：
- annual_return=0% → 30分，100% → 70分，差距从22提升到40
- annual_return=-100% → 0分，500% → 100分
- 全量测试通过

---

### 需求3：精简评分维度（P1 - 设计优化）

**问题**：11个维度高度相关，实际只有3个独立信号。导致权重表具有欺骗性，用户以为在精细调控实际只是在调3个粗粒度旋钮。

**精简方案**：

| 保留维度 | 衡量什么 | 删除的重复维度 | 删除原因 |
|---------|---------|--------------|---------|
| annual_return | 收益 | - | 核心维度 |
| sharpe_ratio | 风险调整收益 | sortino_ratio | 与sharpe高度相关(>0.8) |
| max_drawdown | 尾部风险 | consecutive_losses | 与drawdown相关 |
| profit_factor | 盈亏质量 | win_rate | 被profit_factor覆盖，且归一化区间过窄 |
| monthly_consistency | 时间稳定性 | r_squared | 鼓励过拟合曲线 |

保留5个独立维度，删除 sortino_ratio、calmar_ratio、win_rate、max_consecutive_losses、r_squared。

**涉及文件**：
- `core/scoring/templates.py` - 所有模板的 weights 只包含5个维度
- `core/scoring/normalizer.py` - 删除不再使用的归一化分支（可保留但标记deprecated）
- `core/scoring/scorer.py` - 无需修改（通用加权逻辑）
- `core/scoring/metrics.py` - compute_metrics 仍可计算所有指标（供展示），但只有5个参与评分

**验证标准**：
- 所有模板的 weights 字典只包含5个key
- weights 总和 = 1.0
- 进化任务创建和运行正常
- 全量测试通过

### 需求4：设计3套差异化评分模板（P1 - 设计优化）

**设计原则**：
- 三套模板不只是权重不同，评分逻辑本身不同（收益门槛、回撤处理方式、维度数量）
- 每套模板有明确的适用场景

#### 模板1：收益探索 (explorer)

**适用场景**：探索新市场/新品种，回答"这个标的有无规律"

**评分逻辑**：
```
维度与权重：
  annual_return:       35%
  sharpe_ratio:        20%
  profit_factor:       15%
  max_drawdown:        15%
  monthly_consistency: 10%
  trade_count_penalty:  5%（通过 sigmoid 惩罚）

threshold: 50.0
无收益门槛约束
```

#### 模板2：稳健收益 (optimizer)

**适用场景**：日常策略生产，回答"给我一个能实盘用的策略"

**评分逻辑**：
```
维度与权重：
  sharpe_ratio:        25%
  annual_return:       20%
  monthly_consistency: 20%
  profit_factor:       15%
  max_drawdown:        15%
  trade_count_penalty:  5%

threshold: 65.0
硬约束（低于门槛直接0分）：
  annual_return < 10%  → 0分
  max_drawdown > 60%   → 0分
```

#### 模板3：极致收益 (max_return)

**适用场景**：激进投资者，回答"我要最高收益，不怕波动"

**评分逻辑**：
```
维度与权重：
  annual_return:       50%
  profit_factor:       25%
  sharpe_ratio:        15%
  trade_count_penalty: 10%

threshold: 40.0
无回撤惩罚维度
无收益门槛约束
```

**涉及文件**：
- `core/scoring/templates.py` - 重新定义 SCORING_TEMPLATES
- `core/scoring/scorer.py` - 支持模板级别的硬约束（收益门槛、回撤门槛）
- `api/schemas.py` - 更新 score_template 字段的枚举值
- `web/` 前端 - 更新模板选择器的选项和说明文案

**验证标准**：
- 三套模板的 weighted sum 逻辑正确，总分合理分布在 0-100
- optimizer 模板的硬约束生效：低收益/高回撤策略直接0分
- 前端可选择新模板
- 进化任务使用新模板运行正常
- 全量测试通过

### 需求5：向后兼容处理（P1）

**问题**：现有进化任务和已保存的策略使用旧模板名（balanced、profit_first、steady 等），需要兼容。

**处理方案**：
- 保留旧模板名作为别名，映射到新模板：
  - `balanced`、`steady`、`custom` → `optimizer`
  - `aggressive`、`profit_first` → `explorer`
  - `conservative`、`risk_first` → `optimizer`（保守用户映射到稳健）
- `get_template()` 函数处理别名映射
- 已有数据库中的 score_template 字段无需迁移，读取时自动映射

**涉及文件**：
- `core/scoring/templates.py` - 添加别名映射逻辑

**验证标准**：
- 旧模板名（balanced、profit_first 等）仍可正常使用
- 映射到对应的新模板
- 已有任务的评分结果不受影响

---

### 需求6（未来）：样本外验证（P2 - 架构改动，本期不做）

**问题**：当前所有指标都在训练数据上计算。进化200代、每代15个个体，等于在同一数据集上测试3000个策略变体。即使随机策略也可能偶然产生漂亮的回测曲线。这是过拟合的根源。

**方案概述**：
- 将回测数据按时间切分：前70%为训练集（IS），后30%为验证集（OOS）
- 进化过程在训练集上运行
- champion 策略在验证集上独立评分
- 最终分数 = IS分数 × α + OOS分数 × (1-α)
- 策略简约度作为额外维度：基因数量越少，简约度加分越高

**本期状态**：不实施，记录为未来需求。
