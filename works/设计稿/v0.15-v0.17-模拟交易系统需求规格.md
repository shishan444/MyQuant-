# v0.15 - v0.17 模拟交易系统 需求规格说明书

## 1. 概述

### 1.1 版本范围

| 版本 | 主题 | 提交 | 变更规模 |
|------|------|------|---------|
| v0.15 | PositionManager + 合约数据源 | `946246c` | 5 文件, +900 行 |
| v0.16 | Runner + DB + API + WebSocket | `2959720` | 10 文件, +1822 行 |
| v0.17 | 前端对接真实 API | `e293eb2` | (含在 v0.16 统计中) |
| 测试框架 | 基础设施 + 覆盖补充 | `5b245af` | 12 文件, +856 行 |

### 1.2 核心目标

将进化系统产出的策略 DNA 投入实时模拟交易环境，通过逐 Bar 复现策略逻辑，在真实市场数据上跟踪持仓、盈亏和资金变化，为策略上实盘提供最终验证。

### 1.3 系统边界

```
策略库页面                     模拟交易页面
    |                              |
    v                              v
POST /api/trading/tasks    GET /api/trading/tasks
    |                              |
    v                              v
TradingRunner (后台线程) ←→ PositionManager (状态机)
    |                              |
    v                              v
Binance Futures API         SQLite (任务/交易记录)
```

## 2. v0.15 需求：PositionManager + 合约数据源

### 2.1 N-P01 PositionManager 核心状态机

**需求描述**：实现纯 Python 仓位管理状态机，逐 Bar 处理交易信号，镜像回测引擎 (`engine.py order_func_nb`) 的执行逻辑。

**功能需求**：

| ID | 需求项 | 说明 |
|----|--------|------|
| N-P01-01 | 多空开仓 | 根据 `direction` 参数开 long/short 仓位 |
| N-P01-02 | 信号平仓 | 收到 exit_signal 时按 bar_close 平仓 |
| N-P01-03 | 止损触发 | Long: `bar_low <= entry * (1 - sl)`；Short: `bar_high >= entry * (1 + sl)` |
| N-P01-04 | 止盈触发 | Long: `bar_high >= entry * (1 + tp)`；Short: `bar_low <= entry * (1 - tp)` |
| N-P01-05 | 止损优先 | 同一 Bar 内 SL 先于 TP 检查 |
| N-P01-06 | 强制清算 | 杠杆 > 1 时，equity < maintenance 即触发；`maintenance = init_cash * (1 - 0.9 / leverage^2)` |
| N-P01-07 | 加仓信号 | 加仓时按加权平均价更新 entry_price |
| N-P01-08 | 减仓信号 | 减仓不改变 entry_price，按比例释放 margin |
| N-P01-09 | 资金费率 | 杠杆 > 1 时按 Bar 扣除：`cost_rate = RATE_PER_8H * (hours/8) * ((leverage-1)/leverage)` |
| N-P01-10 | 权益快照 | 每 Bar 结束时记录 equity/unrealized_pnl/balance |
| N-P01-11 | 单向模式 | 仅在 position == None 时允许开仓（非对冲模式） |

**处理优先级**（每 Bar 内）：

```
1. 清算检查 (leverage > 1)
2. SL/TP 检查 (使用 HIGH/LOW 价格)
3. Exit 信号
4. Entry 信号 (仅空仓时)
5. Reduce 信号
6. Add 信号
7. Funding 扣除
```

**输入输出**：

```python
# 输入
pm.process_bar(
    bar_time: str,           # ISO 格式时间
    bar_high: float,         # Bar 最高价
    bar_low: float,          # Bar 最低价
    bar_close: float,        # Bar 收盘价
    entry_signal: bool,      # 开仓信号
    exit_signal: bool,       # 平仓信号
    add_signal: bool,        # 加仓信号
    reduce_signal: bool,     # 减仓信号
    direction: float,        # 1.0=多, -1.0=空
) -> List[dict]              # 事件列表

# 输出事件类型
# {"type": "position_opened", "side": ..., "entry_price": ..., "quantity": ...}
# {"type": "position_closed", "side": ..., "entry_price": ..., "exit_price": ..., "pnl": ..., "exit_reason": "signal|sl|tp|liquidation"}
# {"type": "position_added", "quantity_added": ..., "new_entry_price": ...}
# {"type": "position_reduced", "quantity_reduced": ..., "pnl": ...}
```

**与回测引擎的差异**：

| 差异点 | 回测引擎 | PositionManager |
|--------|---------|----------------|
| 执行时机 | 信号延迟 1 Bar | 当前 Bar 立即执行 |
| Funding | 事后统一计算 | 每 Bar 实时扣除 |
| 余额跟踪 | 内部账户 | 显式 balance/margin 追踪 |

### 3.2 N-R02 TradingRunner 后台线程

**需求描述**：守护线程轮询 SQLite，获取 pending 任务并通过 PositionManager 执行。

**状态流转**：

```
pending → running → stopped
                ↘ paused → pending → running → stopped
```

| ID | 需求项 | 说明 |
|----|--------|------|
| N-R02-01 | 任务轮询 | 每 2 秒轮询 pending 任务，按创建时间升序取第一个 |
| N-R02-02 | 单任务执行 | 同一时间只执行一个任务（`_active_task_id` 互斥） |
| N-R02-03 | 历史回放 | 加载本地 parquet 数据，计算指标和信号，逐 Bar 通过 PM |
| N-R02-04 | 实时获取 | 回放完成后，按 timeframe 对应的轮询间隔获取新数据 |
| N-R02-05 | 状态持久化 | 每个处理周期后保存 PM 状态到 DB（balance、position、stats） |
| N-R02-06 | 断点恢复 | 从 `last_bar_time` 开始回放，恢复 PM 的 position/balance |
| N-R02-07 | 协作停止 | TaskController + threading.Event 实现可中断执行 |
| N-R02-08 | 崩溃恢复 | 启动时将 running 状态任务标记为 stopped（crash_recovery） |
| N-R02-09 | WS 推送 | 状态变化时通过 WS 推送 position_update 消息 |
| N-R02-10 | 数据缺失处理 | 无 parquet 数据时标记任务为 stopped (no_data) |

**Poll 间隔映射**：

```
1m → 60s, 5m → 300s, 15m → 900s, 30m → 1800s
1h → 3600s, 4h → 14400s, 1d → 86400s
实际等待 = min(bar_interval, 60s)
```

**涉及文件**：`core/trading/runner.py`（469 行）

### 3.3 N-R03 REST API 路由

**需求描述**：提供模拟交易任务的 CRUD 和控制接口。

| 端点 | 方法 | 说明 | 请求/响应 |
|------|------|------|----------|
| `/api/trading/tasks` | POST | 创建任务 | req: PaperTradingTaskCreate → res: PaperTradingTaskResponse (201) |
| `/api/trading/tasks` | GET | 列出任务 | query: status?, limit?, offset? → res: PaperTradingTaskListResponse |
| `/api/trading/tasks/{task_id}` | GET | 查询单个 | res: PaperTradingTaskResponse (404 if not found) |
| `/api/trading/tasks/{task_id}/stop` | POST | 停止任务 | res: PaperTradingTaskResponse (400 if status invalid) |
| `/api/trading/tasks/{task_id}/pause` | POST | 暂停任务 | 仅 running 可暂停 |
| `/api/trading/tasks/{task_id}/resume` | POST | 恢复任务 | 仅 paused 可恢复 |
| `/api/trading/tasks/{task_id}/trades` | GET | 交易记录 | query: limit? → res: PaperTradeListResponse |
| `/api/trading/runner-status` | GET | Runner 状态 | res: {is_alive, active_task_id} |

**状态约束**：

| 操作 | 允许的当前状态 | 目标状态 |
|------|--------------|---------|
| stop | running, pending | stopped (reason=user_stop) |
| pause | running | paused |
| resume | paused | pending |

**Stop 双重保障**：同时通过 TaskController 发送停止信号 + 更新 DB 状态。

**涉及文件**：`api/routes/trading.py`（191 行）

### 3.4 N-R04 WebSocket 端点

**需求描述**：提供实时交易状态推送。

| ID | 需求项 | 说明 |
|----|--------|------|
| N-R04-01 | WS 连接 | `/ws/trading/{task_id}`，连接后发送 subscribed 消息 |
| N-R04-02 | 初始快照 | 连接时发送当前任务状态（仅 running/paused/pending/completed） |
| N-R04-03 | 实时推送 | Runner 通过 `asyncio.run_coroutine_threadsafe()` 桥接到 async WS |
| N-R04-04 | Ping/Pong | 客户端发送 `{"type": "ping"}` → 服务端返回 `{"type": "pong"}` |
| N-R04-05 | 断线清理 | WebSocketDisconnect 时从 manager 移除 |

**消息协议**：

```
Server → Client:
  {"type": "subscribed", "task_id": "..."}
  {"type": "task_snapshot", "task_id": "...", "status": "...", "position_side": ..., ...}
  {"type": "task_started", "task_id": "..."}
  {"type": "position_update", "task_id": "...", "position": {...}, "balance": ..., "equity": ..., "unrealized_pnl": ..., "total_trades": ..., "total_pnl": ...}

Client → Server:
  {"type": "ping"}
```

**涉及文件**：`api/routes/ws.py`
