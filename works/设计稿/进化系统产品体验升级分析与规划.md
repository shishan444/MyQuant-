# 进化系统产品体验升级分析与规划

> 日期: 2026-04-20
> 状态: 待实施

## 一、问题发现与根因分析

### 1.1 问题总览

通过代码级验证，确认进化系统存在6项产品设计层面的问题，按影响程度排序：

| 编号 | 问题 | 严重度 | 根因类型 |
|------|------|--------|----------|
| P4 | 高分策略无产出机制，系统看似"空转" | **致命** | 管道缺失 |
| P1 | 策略列表无分页，超限后静默丢失 | 高 | 机制缺失 |
| P6 | 策略去重未实现，可能重复探索 | 高 | 实现遗漏 |
| P2 | 策略展示缺少名称和清晰信息 | 中 | 产品设计缺失 |
| P3 | 历史探索表格信息冗余 | 中 | 产品设计缺失 |
| P5 | 连续进化方向固定，限制搜索覆盖 | 低 | 架构约束 |

---

### 1.2 P4: 高分策略无产出机制（致命）

**用户感知**: 进化运行产出了很多>=80分的策略，但没有一个"策略成果"的概念将它们独立呈现。从用户视角看，系统只有"运行记录"，没有"产出"。

**代码验证**:

```
数据流追踪:
  进化每代完成
    → save_snapshot() 保存整个种群(15个体)到 population_json  ← 数据存在
    → generation_snapshot.best_dna 每代1个个体                   ← 部分可见

  API查询 get_task_strategies
    → SELECT best_dna FROM generation_snapshot LIMIT 10          ← 只读每代最优
    → population_json 中的其余14个个体被完全丢弃                  ← 数据浪费

  strategy表
    → 设计了 source='evolution' + source_task_id 字段            ← 字段存在
    → 进化过程中从未调用 save_strategy()                          ← 管道断裂
```

**根因**: `strategy` 表设计了进化来源字段，但策略提取管道从未实现。进化产出的高分策略被埋在 `generation_snapshot.population_json` 中，没有代码将其提取到独立的 `strategy` 表。

**关键代码位置**:
- `api/runner.py:213-227` — save_snapshot 每代保存，无分数过滤
- `api/routes/evolution.py:367-371` — API只读best_dna，LIMIT 10
- `api/db_ext.py:214-242` — save_strategy 函数存在但进化过程从未调用
- `web/src/components/evolution/TaskDetailDrawer.tsx:337-385` — 快照Tab无操作按钮

---

### 1.3 P1: 策略列表无分页（高）

**代码验证**:

| 层级 | 现状 | 代码位置 |
|------|------|----------|
| 前端请求 | 固定 `limit: 20`，无 offset | `Evolution.tsx:97` |
| 后端API | 只有 `limit` 无 `page/offset` | `evolution.py:237-245` |
| DB查询 | SQL 只有 `LIMIT` 无 `OFFSET` | `db.py:233-251` |
| total字段 | `total=len(items)`（返回数=总数） | `evolution.py:245` |
| 组件渲染 | `map()` 全量渲染 | `StrategyList.tsx:88-98` |

**根因**: 分页机制从未实现。后端SQL、API参数、前端组件三层全部缺失分页能力。当前最多只能看到最近20条任务，超出的策略被静默丢弃。

**补充**: 前端 service 层定义了 `offset` 参数（`services/evolution.ts:9-16`），但后端 API 不接收，该参数形同虚设。

---

### 1.4 P6: 策略去重未实现（高）

**代码验证**:

```python
# population.py:413 — 参数已声明
exclude_signatures: Optional[set] = None

# population.py:428-496 — 函数体中从未引用此参数（死代码）
# engine.py — evolve() 从未接受/传递 exclude_signatures
# runner.py — 连续进化循环无签名累积
```

**根因**: 去重机制预留了接口（`exclude_signatures` 参数 + `_gene_signature` 签名函数），但跨种群传递和过滤的实现被跳过。连续进化盲目开始新种群，可能重复探索相同策略空间。

**签名函数现状** (`diversity.py:10-27`):
- 格式: `"RSI,p=14:lt:entry_trigger|EMA,p=50:price_above:entry_guard|lev:1|dir:long"`
- 局限: 仅取首个参数值（非完整参数对比），不包含 MTF layers
- 仅用于单种群内多样性检测，无跨种群累积

---

### 1.5 P2: 策略展示缺少名称（中）

**代码验证**:
- `EvolutionTask` 全链路无 `name`/`title` 字段（DB→API schema→TS类型）
- 卡片标题 = `getDnaIndicators()` 输出: `EMA(20)+RSI(14)`（技术拼接）
- `effectiveStrategies` 仅过滤不排序（`Evolution.tsx:141-150`），排名取决于后端返回顺序
- 保存策略时有名称模板 `${symbol} ${timeframe} 进化策略`（`Evolution.tsx:283`），但仅在手动保存时使用

**根因**: 策略展示从未做过产品设计。当前展示是纯工程视角的指标拼接，缺少面向用户的命名、分类和摘要。

---

### 1.6 P3: 历史探索表格信息冗余（中）

**代码验证**:
- `HistoryTable.tsx` 展示11列: 交易对、周期、模式、杠杆、方向、目标、最优分、用时、状态、数据范围、可信度
- 缺少: 产出达标策略数、最佳策略核心特征、探索效率
- "最优分"列与"发现策略"区域重复展示

**根因**: 表格从工程字段直出，未从用户决策视角设计信息架构。

---

### 1.7 P5: 连续进化方向固定（低）

**代码验证**:
- `api/runner.py:139` — direction 从任务行读取一次，整个生命周期不变
- `engine.py:158-162` — 每代强制将所有个体的 direction 重置为引擎固定值（mixed除外）
- 连续进化循环（L282-338）创建新种群时复用同一个 direction 变量
- `mutate_risk` 变异算子不包含 direction 变异

**根因**: direction 被设计为任务级约束（创建时确定、运行时锁定），不是种群级探索参数。连续进化每轮新建种群时没有重选机制。

## 二、解决方案设计

### 2.1 版本规划

| 版本 | 内容 | 优先级 | 预期改动量 |
|------|------|--------|-----------|
| **V1** | P4(策略提取) + P1(分页) + P6(去重) | 最高 | ~11个文件 |
| **V2** | P2(命名重设计) + P3(历史表格重设计) | 中 | ~5个文件 |
| **V3** | P5(方向重选) | 低 | ~3个文件 |

---

### 2.2 V1 详细方案

#### V1-P4: 策略自动提取管道

**设计思路**: 在进化过程中，当个体分数达到阈值时自动提取到 `strategy` 表，并通过 WS 实时通知前端。

**后端改动**:

1. **`api/runner.py`** — `on_generation` 回调增加策略提取:
   ```
   进化每代完成
     → 遍历 engine._population 所有个体
     → 个体._eval_diagnostics.score >= strategy_threshold
     → _gene_signature(个体) 未在 explored_signatures 集合中
     → save_strategy(source='evolution', source_task_id=task_id, name=自动生成)
     → explored_signatures.add(signature)
     → _push_ws({type: "strategy_discovered", ...})
   ```

2. **`api/routes/evolution.py`** — 新增端点:
   ```
   GET /tasks/{task_id}/discovered-strategies?min_score=80&page=1&page_size=10
   → 从 strategy 表查询 source_task_id = task_id
   → 支持分数过滤和分页
   → 返回 {items: Strategy[], total: int}
   ```

3. **`api/schemas.py`** — 任务创建 schema 增加 `strategy_threshold: float = 80.0`

**前端改动**:

4. **`web/src/pages/Evolution.tsx`** — 数据源切换:
   - "发现策略"区域从 effectiveStrategies(任务列表) 改为调用新API
   - WS处理增加 `strategy_discovered` 事件监听
   - 新策略到达时自动更新列表（Query Cache invalidate）

5. **`web/src/types/api.ts`** — 新增类型:
   ```typescript
   interface DiscoveredStrategy {
     strategy_id: string;
     name: string;
     score: number;
     dna: DNA;
     source_task_id: string;
     generation: number;
     created_at: string;
   }
   ```

6. **`web/src/hooks/useEvolution.ts`** — WS `strategy_discovered` 事件处理

**阈值产品设计**: 默认80分（可在任务创建时调整）。低于阈值的策略仍保存在 snapshot 中（不丢失），但不出现在"发现策略"列表。用户看到的是"达标产出"。

---

#### V1-P1: 分页与过滤

**后端改动**:

1. **`core/persistence/db.py`**:
   - `list_all_tasks` 增加 `offset` 参数，SQL 改为 `LIMIT ? OFFSET ?`
   - 新增 `count_all_tasks(db_path, status=None)` 返回真实总数

2. **`api/routes/evolution.py`**:
   - `list_tasks` 增加 `page: int = 1` 参数，计算 offset = (page-1) * page_size
   - `total` 改为调用 `count_all_tasks` 返回真实值

**前端改动**:

3. **`web/src/services/evolution.ts`** — 传递 page + page_size

4. **`web/src/components/evolution/StrategyList.tsx`**:
   - Props 增加 page/pageSize/total/onPageChange
   - 底部增加分页组件
   - 增加分数过滤下拉（全部 / >= 60 / >= 80 / >= 100）

---

#### V1-P6: 策略去重

**后端改动**:

1. **`core/evolution/diversity.py`** — 签名函数增强:
   ```python
   # 当前: 只取首个参数值
   first_key = next(iter(gene.params))
   param_summary = f",p={gene.params[first_key]}"

   # 改为: 取全部参数的稳定排序哈希
   param_parts = sorted(f"{k}={v}" for k, v in gene.params.items())
   param_summary = ",".join(param_parts)
   ```

2. **`core/evolution/population.py`** — 实现 `exclude_signatures`:
   - `_dna_from_template` 生成后检查签名，命中则跳过
   - `create_random_dna` 生成后检查签名，命中则重试（最多3次）
   - 在 init_population 的人口处过滤

3. **`core/evolution/engine.py`** — `evolve()` 增加 `exclude_signatures` 参数:
   - 传递给 `init_population`
   - 新鲜血液注入时过滤

4. **`api/runner.py`** — 连续进化循环维护签名集合:
   ```python
   explored_signatures: set = set()
   # 每轮进化完成后:
   for ind in engine._population:
       explored_signatures.add(_gene_signature(ind))
   # 下一轮传入:
   result = engine.evolve(..., exclude_signatures=explored_signatures)
   ```

### 2.3 V2 方案概要

#### V2-P2: 策略命名与展示重设计

**命名规则**:
```
{策略类型} {方向} {周期}
例: "EMA趋势 做多 4H" / "均值回归 做空 15m"
```

**策略类型推导** (从DNA信号基因判断):
- 趋势型: 包含 EMA/SMA + ADX/MA交叉
- 动量型: 包含 RSI/MACD/Stochastic
- 均值回归: 包含 BB + RSI超买超卖
- 波动率: 包含 BB带宽 + ATR
- 多周期: 包含 layers

**卡片信息架构**:
```
+------------------------------------------+
| [策略类型标签]  EMA趋势 做多 4H    85.3分 |
| 年化 +120.5%  夏普 2.31  回撤 -18.2%     |
| 核心: EMA(9)/EMA(21)金叉 + ADX趋势确认   |
| [可视化验证] [保存] [继续进化]            |
+------------------------------------------+
```

#### V2-P3: 历史探索表格重设计

**核心列**: 时间 / 产出数(>=80) / 最高分 / 探索代数 / 探索效率 / 操作

**新增"产出数"列**: 从 strategy 表统计 `source_task_id = task_id` 的达标策略数量

---

### 2.4 V3 方案概要

#### V3-P5: 连续进化方向重选

**方案A — 轮转策略**:
```python
directions = ["long", "short", "mixed"]
# 每轮新种群:
direction = directions[population_count % 3]
```

**方案B — 随机选择**:
```python
direction = random.choice(["long", "short", "mixed"])
```

**推荐方案A**: 轮转保证三个方向均匀覆盖，随机可能连续命中同一方向。

**实现位置**: `api/runner.py` 连续进化循环（L282-338），在新种群创建前重设 direction。

## 四、验证标准

### V1 验收条件

1. **策略提取**: 进化过程中分数>=80的个体自动保存到strategy表，前端"发现策略"区域实时显示
2. **分页**: 策略列表支持翻页，后端返回正确的total，前端展示分页控件
3. **去重**: 连续进化中，已探索签名不会在新种群中重复生成（通过签名集合验证）
4. **WS实时**: 新策略产出时前端实时更新，无需手动刷新
5. **向后兼容**: 现有进化任务不受影响，strategy_threshold默认值确保旧任务行为不变

### 测试计划

- `tests/test_strategy_extraction.py` — 策略提取管道单元测试
- `tests/test_dedup.py` — 跨种群去重集成测试
- `tests/test_pagination.py` — 分页API测试
- 手动前端测试: 创建进化任务 → 观察策略产出 → 验证分页和过滤
