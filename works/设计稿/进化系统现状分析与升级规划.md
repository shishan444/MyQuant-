## 一、当前系统运作全景

### 1.1 整体流程

```
用户点击"开始探索"
       |
       v
  [创建任务] -- 传入: 交易对、周期、优化目标、指标池
       |
       v
  [生成初始种群] -- 15个随机策略(个体)
       |
       v
  [进化循环] <-----------------------------------\
       |                                          |
       v                                          |
  [逐个回测评估] 每个策略 -> 得分(0-100)            |
       |                                          |
       v                                          |
  [淘汰+繁殖] 保留精英(40%), 交叉+变异产生新个体    |
       |                                          |
       v                                          |
  [注入新鲜血液] 随机1~2个全新策略                   |
       |                                          |
       v                                          |
  [检查停止条件] -- 未达标则继续 -------------------/
       |
       v (达标/停滞/衰退/达到上限)
  [连续模式: 以冠军为祖先开启新种群]  <-- BUG: 达标后不开启
       |
       v
  [输出冠军策略]
```

### 1.2 一个策略(DNA)的结构

```
策略 DNA
|
|-- 信号基因 (2~4个指标组合, 固定结构)
|   |
|   |-- 入场触发(必须1个): 如 RSI(14) < 30
|   |-- 入场条件(50%概率): 如 EMA(50) 价格在上方
|   |-- 出场触发(必须1个): 如 MACD histogram 上穿0
|   |-- 出场条件(40%概率): 如 BB(20,2) 价格在下方
|
|-- 逻辑基因
|   |-- 入场逻辑: AND 或 OR (随机)
|   |-- 出场逻辑: AND 或 OR (随机)
|
|-- 风控基因
|   |-- 止损: 1%~15% 随机
|   |-- 仓位: 10%~60% 随机
|   |-- 止盈: 通常无
|
|-- 执行基因
|   |-- 交易对: BTCUSDT, 周期: 4h
```

### 1.3 指标池(39个)

```
趋势类(6):    EMA, SMA, WMA, DEMA, TEMA, VWAP
动量类(9):    RSI, MACD, Stochastic, CCI, ROC, Williams%R, Aroon, CMO, TRIX
波动类(4):    BB, ATR*, Keltner, Donchian          * = 只能做条件
成交量类(8):  OBV, CMF, MFI, RVOL, VROC, AD, CVD, VWMA
趋势强度(2):  ADX*, PSAR*                          * = 只能做条件
形态类(10):   看跌吞没, 黎明之星, 三白兵, 三乌鸦...
结构类(1):    VolumeProfile*                        * = 只能做条件
```

### 1.4 当前探索方式

| 环节 | 当前做法 | 说明 |
|------|---------|------|
| 指标选择 | 39个完全等概率随机 | 无偏好, 无权重 |
| 参数取值 | EMA有候选值[7,15,20,30,60,90]; 其余全范围均匀随机 | 仅1个指标有预设 |
| 条件类型 | 从指标支持的条件列表中随机选 | RSI阈值有预设[25,30,35,40,60,65,70,75]; 其余[-1,1]随机 |
| 角色分配 | 8个角色只用了4个(入场/出场触发+条件) | 加仓/减仓完全未探索 |
| 策略结构 | 固定2~4个指标 | 不探索更多/更少 |
| 交叉操作 | 取父A入场基因 + 父B出场基因 | 粗糙但存在 |
| 变异操作 | 7种(参数微调/指标替换/逻辑翻转/风控调整/增删条件/跨层逻辑) | 缺差分进化/多项式变异等 |
| 变异强度 | 根据停滞自适应(1~4次变异) | 有基本自适应能力 |
| 选择方式 | 排名选择, 精英比例40% | 无锦标赛, 无多目标 |
| 连续探索 | 达标后停止(BUG), 且只支持2级种群 | 需改为真正循环 |
| 评分体系 | 5维加权(年化/夏普/回撤/胜率/卡玛) | 缺Sortino/盈亏比/稳定性 |

### 1.5 评分体系

```
当前4个评分模板:

利润优先:  年化35% + 夏普25% + 回撤25% + 胜率15%
稳健优先:  年化20% + 夏普35% + 回撤35% + 卡玛10%
风控优先:  年化10% + 夏普30% + 回撤40% + 卡玛20%
自定义:    各20%均分

交易次数 < 10: 总分线性折扣
优化目标只影响评分权重, 不影响搜索策略
```

## 二、问题诊断

### 问题 1: 连续探索在达标后停止(BUG)

**位置**: `api/runner.py` 第284行

**当前逻辑**:
```
if continuous and stop_reason not in ("error",) and not target_reached:
    # 开启新种群
```

**问题**: `not target_reached` 导致找到好策略后就停止连续探索。

**附带问题**: 当前只支持两级连续(最多2个种群), 第二次 `engine.evolve()` 后没有 while 循环。

**影响**: 进化任务的"连续探索"承诺无法兑现, 达标即停。

### 问题 2: 指标探索完全随机, 缺乏金融常识

当前搜索空间估算:
```
39个指标 x 各自参数空间 x 多种条件类型 x 随机阈值 x 多种角色
= 数百万种组合
```

其中 90%+ 是不合理组合:

| 不合理组合 | 出现原因 | 正确做法 |
|-----------|---------|---------|
| RSI > 75 做入场做多 | 阈值在[-1,1]随机 | RSI<30才做多 |
| ATR 做入场触发 | 随机分配角色 | ATR只应做止损/仓位管理 |
| 形态指标独立做入场 | 随机组合 | 需搭配动量/趋势确认 |
| MACD 参数(5,60,1) | 参数全范围随机 | 共识参数(12,26,9) |
| EMA(137) 做趋势判断 | 参数均匀随机 | 关键均线7/20/50/100/200 |

**金融共识(来自研究)**:

10个核心指标有高度一致的参数和用法:

| 指标 | 共识参数 | 共识角色 | 共识条件 |
|------|---------|---------|---------|
| RSI | 周期14 | 入场/出场触发 | <30超买多, >70超卖空 |
| MACD | 12/26/9 | 入场/出场触发 | 金叉/死叉(直方图上穿/下穿0) |
| BB | 20, 2.0 | 入场/出场条件 | 触下轨做多, 触上轨做空 |
| ATR | 14 | 出场条件(止损) | ATR*2或ATR*3作为止损距离 |
| ADX | 14 | 入场条件(过滤) | >25趋势确立, <20无趋势 |
| Stochastic | 14/3/3 | 入场/出场触发 | <20超卖金叉做多, >80超买死叉 |
| EMA | 7/20/50/100/200 | 入场条件 | 价格在上方/下方, 金叉/死叉 |
| PSAR | 0.02/0.2 | 出场触发 | 翻转做多/做空 |
| CCI | 14 | 入场条件 | <-100超卖, >+100超买 |
| Williams%R | 14 | 入场触发 | <-80超卖, >-20超买 |

7种经典搭配模式:
1. 趋势跟踪: EMA(50/200) + ADX(14) + ATR(14)止损
2. 动量交易: RSI(14) + MACD(12/26/9) + BB(20,2)
3. 均值回归: BB(20,2) + RSI(14) + Stochastic(14,3,3)
4. 趋势过滤: ADX(14)作过滤器 + 任意入场指标
5. 量价确认: OBV/AD + MACD + 价格突破
6. 波动率突破: BB(20,2) + Keltner(20) Squeeze + MACD
7. 日内交易: VWAP + RSI(7) + MACD + Volume

### 问题 3: 高层架构设计缺陷

#### 3.1 策略表达能力受限

```
当前: 固定 2~4 个指标
实际交易需求:
  - 简单策略: 2个指标(如 RSI+EMA)
  - 中等策略: 4个指标(如 RSI+MACD+BB+ADX)
  - 复杂策略: 6个指标(如 多周期+多层过滤)
```

**影响**: 无法表达复杂的交易逻辑。

#### 3.2 连续种群知识传递断裂

```
当前: 新种群只继承冠军1个个体
问题: 前一个种群的集体经验(top 3~5名)全部丢失
```

**影响**: 每个新种群几乎从零开始, 进化效率低。

#### 3.3 选择压力过强

```
当前: 精英比例40%, 新鲜血液仅1~2个
建议: 精英比例20~30%, 新鲜血液3~5个
```

**影响**: 种群过早收敛到局部最优。

#### 3.4 优化目标不影响搜索策略

```
当前: "利润优先"和"风控优先"搜索的路径完全相同, 只有评分不同
问题: 风控优先应该更频繁变异止损参数, 利润优先应该更频繁变异入场参数
```

**影响**: 优化目标的区分度不足。

### 问题 4: 变异操作有改进空间

当前7种变异 vs 业界可用方法对比:

| 能力 | 当前状态 | 差距 |
|------|---------|------|
| 参数微调 | 有, 均匀随机微调 | 应改为高斯/多项式, 更科学 |
| 指标替换 | 有, 同类替换 | 合理 |
| 逻辑翻转 | 有 | 合理 |
| 风控调整 | 有 | 合理 |
| 增删条件 | 有 | 合理 |
| 交叉操作 | 有(粗糙) | 仅入场/出场基因交换, 缺参数空间交叉 |
| 自适应变异强度 | 部分 | 有停滞检测, 但无步长自适应 |
| 差分进化变异 | 无 | 连续参数优化的黄金标准 |
| 多项式有界变异 | 无 | DEAP内置, 保证参数不越界 |
| 锦标赛选择 | 无 | 比排名选择更通用 |
| 多目标选择(NSGA-II) | 无 | 加权求和简化了多目标问题 |
| 岛屿模型 | 无 | 可并行化, 维护全局多样性 |
| 局部搜索 | 无 | EA+局部搜索可显著提升收敛速度 |
| 自适应算子选择 | 无 | 自动发现最优算子组合 |

### 问题 5: 评分体系不够完善

#### 5.1 缺失的关键维度

| 缺失维度 | 重要性 | 说明 |
|---------|--------|------|
| Sortino比率 | 高 | 只惩罚下行风险, 比夏普更精确 |
| 盈亏比(Profit Factor) | 高 | 比胜率更有意义 |
| 资金曲线线性度(R-squared) | 高 | 理想的资金曲线应接近直线 |
| 最大连续亏损 | 中 | 影响实盘心理承受力 |
| 参数敏感度 | 中 | 参数微调后策略是否崩溃 |
| Walk-Forward比率 | 中 | 检测过拟合的最可靠方法 |

#### 5.2 信息冗余

```
annual_return 和 calmar_ratio 存在信息重叠:
  Calmar = 年化收益 / 最大回撤
  同时使用两者 -> "收益"维度权重偏高
```

#### 5.3 交易次数惩罚过于简单

```
当前: 交易次数 < 10 -> 线性折扣
问题:
  - 阈值太低(10笔交易的统计意义很弱)
  - 没有统计显著性概念
  - 没有区分策略类型

建议: 用Sigmoid平滑过渡, 阈值提高到20~30
```

## 三、升级规划

### 总体原则

```
1. 分层约束: 硬约束(必须遵守) > 推荐用法(70%遵循) > 自由探索(30%)
2. 渐进升级: 按优先级分3批实施, 每批可独立验证
3. 兼容性: 新功能向后兼容, 不破坏已有DNA结构
4. 可观测: 所有改动都需要有度量手段, 能看到效果
```

### Phase 1: 基础修复 (优先级最高, 修复核心问题)

#### 1.1 连续探索BUG修复

**改动文件**: `api/runner.py`

**改动内容**:
- 去掉 `not target_reached` 条件
- 将两次 `engine.evolve()` 改为 while 循环
- 循环内每次检查任务状态(用户是否手动停止)

**改动前**:
```
if continuous and not target_reached:
    开启第二个种群(仅一次)
```

**改动后**:
```
while continuous and task仍在运行:
    以冠军为祖先(或前3名)开启新种群
    执行进化
    更新冠军
```

#### 1.2 指标用法档案系统

**新建文件**: `core/features/indicator_profile.py`

为每个指标建立"推荐用法档案":

```
指标用法档案结构:

IndicatorProfile = {
    "RSI": {
        "recommended_role": ["entry_trigger", "exit_trigger"],    # 推荐角色
        "recommended_params": {"period": [7, 14, 21]},            # 推荐参数
        "recommended_conditions": [                               # 推荐条件
            {"type": "lt", "thresholds": [25, 30, 35]},          # 超卖做多
            {"type": "gt", "thresholds": [65, 70, 75]},          # 超买做空
        ],
        "follow_probability": 0.70,                               # 遵循推荐的概率
    },
    "MACD": {
        "recommended_role": ["entry_trigger", "exit_trigger"],
        "recommended_params": {"fast": [12], "slow": [26], "signal": [9]},
        "recommended_conditions": [
            {"type": "cross_above", "field": "histogram", "thresholds": [0]},
            {"type": "cross_below", "field": "histogram", "thresholds": [0]},
        ],
        "follow_probability": 0.70,
    },
    "BB": {
        "recommended_role": ["entry_guard", "exit_guard"],
        "recommended_params": {"period": [20], "std": [2.0]},
        "recommended_conditions": [
            {"type": "price_below", "field": "lower"},            # 触下轨做多
            {"type": "price_above", "field": "upper"},            # 触上轨做空
        ],
        "follow_probability": 0.70,
    },
    ...
}
```

**分层策略**:

```
当创建或变异一个信号基因时:

70% 概率 -> 从推荐用法档案中采样
            - 角色从 recommended_role 中选
            - 参数从 recommended_params 中选
            - 条件从 recommended_conditions 中选
            - 阈值从 thresholds 中选

30% 概率 -> 自由探索(保持当前的随机逻辑)
            - 允许发现非共识用法
            - 保留进化系统的创新能力
```

**改动文件**: `core/evolution/population.py` 的 `_make_signal()` 和 `core/evolution/operators.py` 的变异函数

#### 1.3 经典搭配模板

**改动文件**: `core/evolution/population.py`

新增 7 种经典搭配模板, 新种群初始化时可从中选一种作为种子:

```
STRATEGY_TEMPLATES = [
```

### Phase 2: 评分体系升级

#### 2.1 新增评估指标

**改动文件**: `core/scoring/metrics.py`

新增计算函数:

| 指标 | 计算方式 | 用途 |
|------|---------|------|
| Sortino比率 | 年化收益 / 下行标准差 | 只惩罚下行风险 |
| Profit Factor | 总盈利 / 总亏损 | 直接衡量盈利能力 |
| R-squared | 净值曲线对线性回归的R^2 | 资金曲线平滑度 |
| 最大连续亏损 | 连续亏损交易的最大次数 | 心理承受指标 |
| 月度收益一致性 | 正收益月数 / 总月数 | 时间分布均匀性 |

#### 2.2 评分维度重构

**改动文件**: `core/scoring/templates.py`

从当前的平面5维, 重构为5大类12个子指标:

```
评分体系(总分100)

收益能力(30分)                    风险控制(25分)
  |-- Sharpe比率(12)               |-- 最大回撤(10)
  |-- Sortino比率(10)              |-- 波动率(8)
  |-- Calmar比率(8)                |-- 最大连续亏损(7)

交易质量(20分)                    稳定性(15分)
  |-- Profit Factor(8)             |-- R-squared(6)
  |-- 期望值(7)                    |-- 月度一致性(5)
  |-- 胜率(5)                      |-- 交易频率稳定性(4)

鲁棒性(10分)
  |-- 参数敏感度(5)
  |-- Walk-Forward比率(5)
```

3套权重方案:

```
均衡型(默认):
  收益30 + 风控25 + 质量20 + 稳定15 + 鲁棒10

激进型(侧重收益):
  收益40 + 风控15 + 质量20 + 稳定15 + 鲁棒10

保守型(侧重风控):
  收益25 + 风控35 + 质量15 + 稳定15 + 鲁棒10
```

#### 2.3 交易次数惩罚改进

**改动文件**: `core/scoring/scorer.py`

从线性折扣改为Sigmoid平滑过渡:

```
当前: penalty = min(1.0, trade_count / 10)

改为: penalty = 1 / (1 + exp(-0.2 * (trade_count - 30)))

效果:
  10笔: penalty = 0.02 (几乎为0)
  20笔: penalty = 0.27
  30笔: penalty = 0.50
  40笔: penalty = 0.73
  50笔: penalty = 0.88
  60笔: penalty = 0.95
```

#### 2.4 Walk-Forward验证默认开启

**改动文件**: `api/runner.py`

当前 WF 验证只对高分策略(>40)且配置了开关才运行。改为:
- 所有策略默认开启简化版WF(3段分割)
- 高分策略(>60)使用完整版WF(5段分割)
- WF比率纳入鲁棒性评分

### Phase 3: 进化算法升级

#### 3.1 参数微调升级: 多项式有界变异

**改动文件**: `core/evolution/operators.py`

替换当前的均匀随机微调, 改为多项式有界变异:

```
当前: new_val = current + random(-1,1) * range * random(0.05, 0.30)
改为: new_val = polynomial_bounded(current, min, max, eta=20)

效果:
  - eta=20: 大部分变异幅度小(精细搜索)
  - eta=2: 变异幅度大(广泛探索)
  - 自动保证参数不越界
  - 根据停滞情况动态调整eta
```

#### 3.2 连续种群知识传递改进

**改动文件**: `api/runner.py`, `core/evolution/population.py`

```
当前: 新种群以冠军1人为祖先
改为: 新种群以冠军+亚军+季军3人为祖先

新种群初始化:
  个体1: 冠军(不变)
  个体2: 亚军(不变)
  个体3: 季军(不变)
  个体4~10: 对3个祖先的变异

```
