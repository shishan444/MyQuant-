# v0.18 - v0.20 模拟交易系统重构 需求规格说明书

## 1. 概述

### 1.1 版本范围

| 版本 | 主题 | 变更规模 |
|------|------|---------|
| v0.18 | 信号过滤 + 虚拟账户 | 4 文件新增, +560 行 |
| v0.19 | Runner 重写 + DB 适配 | 4 文件修改, ~400 行重构 |
| v0.20 | 分批限价单 + ATR 预测 | 3 文件新增, +350 行 |
| 测试框架 | 新增测试覆盖 | 3 文件新增, +700 行 |

### 1.2 核心目标

修正模拟交易系统的三个根本缺陷：执行价格不合理（close → open）、信号直接执行无理性判断（机械交易）、回放阶段冗余且行为不一致。将系统从"回测镜像"转变为"虚拟交易账户"。

### 1.3 架构变更

```
当前 (v0.17)                          重构后 (v0.18)
─────────────                          ─────────────
策略信号 → PositionManager             策略信号 → JudgmentRule → VirtualAccount
          → bar_close 执行                       → pending_decision
          → 机械执行                              → Bar N+1 bar_open 执行
                                                    → 理性过滤

策略引擎   [已有,不改]                  策略引擎   [已有,不改]
     ↓                                       ↓
PositionManager [重构]                JudgmentRule [新增] → VirtualAccount [重构]
     ↓                                       ↓
TradingRunner  [重写]                 TradingRunner [重写]
```

### 1.4 当前版本问题 (代码验证确认)

**涉及文件**：`core/trading/types.py`（新增, ~60 行）

### 2.2 N-T02 信号判定规则

**需求描述**：在策略信号和执行之间增加理性判断层，过滤掉不合理的交易。

**判定规则**（按优先级）：

```
规则 1: exit/reduce + 有持仓
  if bars_held < min_hold_bars → HOLD (持仓时间不够)
  if unrealized_pnl < fee * min_profit_ratio → HOLD (利润不够覆盖交易成本)
  else → CLOSE / REDUCE

规则 2: entry + 无持仓 → OPEN (target * initial_entry_pct, 首次试探)

规则 3: entry + 有同方向持仓
  if unrealized_pnl < 0 AND profit_add_only → HOLD (不逆势加仓)
  if actual_pct < target_pct → ADD (补齐到目标仓位)
  else → HOLD (已满仓)

规则 4: entry + 有反方向持仓 → CLOSE (先平仓，不在同一Bar反向开仓)

规则 5: 无信号
  if 有持仓 AND actual_pct < target_pct AND 盈利中 → ADD (继续补齐)
  else → HOLD

规则 6: max_hold_bars 安全阀
  if 有持仓 AND bars_held >= max_hold_bars AND unrealized_pnl < 0 → CLOSE
```

**关键约定**：

- SL/TP 不经过判定引擎，直接在 VirtualAccount 层执行（风控是硬性规则）
- `profit_add_only` 的"亏损"指未实现盈亏 < 0（非总会话盈亏）
- 判定规则是无状态纯函数：(SignalSet, AccountState) → Decision

**涉及文件**：`core/trading/judgment.py`（新增, ~160 行）

## 3. v0.19 需求：Runner 重写 + DB 适配

### 3.1 N-R01 Runner 核心重构

**需求描述**：重写 TradingRunner，删除全量回放，引入 pending_decision 机制和形成中 Bar 过滤。

**功能需求**：

| ID | 需求项 | 说明 |
|----|--------|------|
| N-R01-01 | pending_decision 机制 | 信号在 Bar N 产生 → 存为 pending_decision → Bar N+1 的 open 执行 |
| N-R01-02 | 新任务无回放 | 新任务直接加载预热数据 → 进入实时循环 |
| N-R01-03 | Resume 最小回放 | Resume 时从 last_bar_time 到最新已完成 Bar 做最小回放（通常 < 100 Bar） |
| N-R01-04 | 形成中 Bar 过滤 | `_filter_forming_bar()`: `bar_time + interval > now` → 排除未收盘 Bar |
| N-R01-05 | 组件创建 | `_make_account()` 创建 VirtualAccount + JudgmentRule |
| N-R01-06 | 指标热身验证 | 启动时检查最后 Bar 的信号列无 NaN，有 NaN 则等待更多数据 |

**单 Bar 处理流程**：

```
Bar N 收盘，系统收到新数据
│
├── Step 0: 形成中 Bar 过滤
│   └── bar_time + interval > now? → 排除
│
├── Step 1: 风控检查 (最高优先级)
│   ├── SL/TP: 用 Bar N 的 high/low 检查，open 价执行
│   └── 清算检查 (leverage > 1 时)
│
├── Step 2: 执行上一 Bar 的决策
│   ├── pending_decision 存在?
│   │   → 是: 用 Bar N 的 open 执行
│   │   → SL/TP 已关闭持仓? → 跳过
│   │   → 否: 跳过
│   └── 清除 pending_decision
│
├── Step 3: 信号评估
│   ├── 计算指标 (compute_all_indicators)
│   └── 生成信号 (dna_to_signal_set)
│
├── Step 4: 判定
│   ├── 输入: SignalSet + AccountState
│   └── 输出: Decision
│
├── Step 5: 存储决策
│   └── Decision != hold? → 存为 pending_decision
│
└── Step 6: 保存 + 推送
    ├── 资金费率扣除
    ├── 权益快照
    ├── 持久化到 DB
    └── WebSocket 推送
```

**形成中 Bar 过滤实现**：

```python
def _filter_forming_bar(self, df, timeframe: str):
    interval_seconds = _BAR_SECONDS.get(timeframe, 14400)
    now = pd.Timestamp.now(tz="UTC")
    last_bar_time = df.index[-1]
    if last_bar_time.tz is None:
        last_bar_time = last_bar_time.tz_localize("UTC")
    if last_bar_time + pd.Timedelta(seconds=interval_seconds) > now:
        return df.iloc[:-1]  # 排除形成中 Bar
    return df
```

**Resume 最小回放实现**：

```python
def _min_replay_for_resume(self, account, judgment, df, task_row, controller):
    last_bar_time = task_row.get("last_bar_time")
    if not last_bar_time:
        return df
    # 找到 last_bar_time 之后的 Bar，用 process_bar_v2 处理
    for i in range(start_idx, len(df)):
        controller.check_stop()
        row = df.iloc[i]
        account.process_bar_v2(
            bar_high=float(row["high"]), bar_low=float(row["low"]),
            bar_open=float(row["open"]), bar_close=float(row["close"]),
            bar_time=df.index[i].isoformat(), pending_decision=None,
        )
    return df
```

**删除的逻辑**：

| 逻辑 | 原位置 | 说明 |
|------|--------|------|
| 全量回放循环 | `runner.py:256-286` | for i in range(start_idx, len(df)) |
| shift(1) 信号处理 | `runner.py:242-249` | replay_entries/exits/adds/reduces |
| checkpoint 每 500 Bar | `runner.py:279-285` | 回放阶段定期保存 |
| dedup paper trades | `runner.py:252-254` | delete_paper_trades_from |

**崩溃恢复约定**：pending_decision 不持久化。进程崩溃时 `recover_stale_trading_tasks()` 标记任务为 stopped，用户手动 restart。Bar N 和 Bar N+1 之间的 pending_decision 丢失，下一个机会在 Bar N+2。

**涉及文件**：`core/trading/runner.py`（重写, 从 524 行简化至 ~300 行）

## 4. v0.20 需求：分批限价单 + ATR 预测

### 4.1 N-E01 价格预测器

**需求描述**：基于 ATR * 动态倍数预测下一 Bar 的价格范围，自适应调整覆盖率。

| ID | 需求项 | 说明 |
|----|--------|------|
| N-E01-01 | PriceRange 数据类 | low, high, confidence, atr_value, multiplier |
| N-E01-02 | 预测公式 | `[close - mult * ATR, close + mult * ATR]` |
| N-E01-03 | 自适应调整 | 覆盖率 < 80% → multiplier += 0.1; 覆盖率 > 90% → multiplier -= 0.1 |
| N-E01-04 | 覆盖率计算 | 实际 high <= 预测 high AND 实际 low >= 预测 low → 覆盖 |

**涉及文件**：`core/trading/prediction.py`（新增, ~150 行）

| N-E02-03 | 成交判定 | 买入限价: bar_low <= limit_price → 成交; 卖出限价: bar_high >= limit_price → 成交 |
