# MyQuant 系统全景：功能、价值与工程保障

## 一、系统定位与核心价值链

MyQuant 解决的核心问题是：**把"我感觉这个策略能赚钱"变成"数据证明这个策略能赚钱"**。

系统从数据到价值的逻辑链路：

```
市场数据 → 指标计算 → 信号生成 → 回测验证 → 进化搜索 → 模拟盘验证 → 前端展示
```

每一层解决的问题和创造的价值不同：

| 层级 | 功能 | 解决什么问题 | 创造什么价值 |
|------|------|-------------|-------------|
| 数据层 | Binance K线获取+多周期合成 | "数据从哪来" | 统一数据入口，消除数据源差异 |
| 特征层 | 40个技术指标+衍生品指标计算 | "市场状态怎么量化" | 把主观判断转化为可计算的数值特征 |
| 信号层 | 基于DNA编码的信号规则引擎 | "什么时候买卖" | 策略逻辑可编码、可变异、可搜索 |
| 预测层 | GARCH价格区间预测 | "价格会到哪里" | 为限价单提供科学定价依据 |
| 回测层 | 历史数据bar-by-bar回放 | "策略过去表现如何" | 快速验证策略假设，淘汰劣质策略 |
| 进化层 | 遗传算法搜索策略空间 | "什么策略最优" | 自动发现人类难以手动设计的策略组合 |
| 模拟层 | 预测性订单管理系统 | "策略在接近真实环境中表现如何" | 验证策略在滑点/延迟/部分成交下的鲁棒性 |
| 展示层 | Web API + 前端 | "结果怎么看" | 将复杂过程可视化为人可理解的决策依据 |

## 二、功能如何逻辑打通

### 2.1 策略编码：StrategyDNA

策略不是代码，是**基因序列**。`StrategyDNA` 是贯穿系统的核心数据结构：

```
StrategyDNA = SignalGenes(信号规则) + LogicGenes(组合逻辑)
            + RiskGenes(风控参数) + ExecutionGenes(执行参数)
```

这个设计的价值在于：策略变成了可以**交叉、变异、评分**的进化个体，而不是一段写死的代码。进化引擎不需要理解策略逻辑，只需要操作基因序列。

### 2.2 信号到交易的完整路径

系统有两条执行路径，通过 `use_limit_orders` 配置开关：

**Legacy路径（直接执行）**：
```
信号检测 → 立即生成决策 → 下一bar以开盘价执行
```

**预测性订单路径（限价单）**：
```
信号检测 → 预测价格区间 → 计算最优挂单价 → 创建限价单
→ 每bar检查：触及价格?→成交 / 信号反转?→撤单 / 超时?→过期
```

两条路径共享同一套风控（SL/TP/清算）和账户管理，区别只在订单执行方式。

### 2.3 预测系统如何增强交易

`PriceRangePredictor` 的作用是回答"下一bar的价格大概在什么范围"：

- **GARCH(1,1)** 建模波动率聚类（波动大之后往往继续大）
- **8个市场因子**（波动率体制、相对波动率、趋势强度等）调整预测宽度
- **动态K值**（miss_streak应急机制 + 因子权重调整）自适应校准

预测结果直接驱动限价单定价：
```
alpha = base + range * confidence
挂单价 = 当前价 * (1 +/- alpha)
```
成交概率通过正态分布CDF计算，学术依据来自 Guo-De Larrard-Rusan 模型。

### 2.4 进化引擎如何搜索策略空间

进化流程：
```
初始化种群 → 评估适应度 → 选择/交叉/变异 → 下一代 → 收敛
```

适应度是**五维加权评分**（收益率、夏普比、最大回撤、胜率、Calmar比），每维通过 Sigmoid 归一化到 [0,1] 后加权求和。这避免了单维度优化导致的策略偏执。

关键设计决策：
- 每个个体评估成本高（需要完整回测），所以种群规模控制在 30-50
- 交叉操作在基因层面进行，不是代码层面
- 变异概率和幅度由 DNA 自身的参数控制

### 2.5 多时间框架（MTF）如何工作

MTF 采用三阶段管线：
```
Layer评估（各周期独立计算信号）
  → 跨层合成（cross-layer权重加权）
  → 决策门控（最终yes/no判断）
```

这解决了单周期信号的滞后性问题——日线趋势向上时，15分钟的卖出信号应该被抑制。

## 三、工程侧如何保障

### 3.1 配置驱动的向后兼容

`use_limit_orders` 开关是典型的例子。新增的预测性订单管理系统不替代原有路径，而是作为可选路径并存。这保证了：
- 已验证的 legacy 路径不受影响
- 新路径可以独立测试和渐进式启用
- 回滚成本为零（改配置即可）

### 3.2 测试覆盖策略

系统采用三层测试：
- **单元测试**（~180个）：验证各模块的独立逻辑正确性
- **集成测试**：验证模块间协作（如 pipeline + predictor + account 的完整流程）
- **端到端场景**（10个）：验证从信号到平仓的完整生命周期

关键测试设计原则：**测试行为契约，不测实现细节**。例如 SL/TP 测试验证"止损以触发价执行，非开盘价"，而不是验证内部计算步骤。

### 3.3 文档与代码对齐

四层文档结构（MAP → Domain → Crosscut → Flows）确保：
- 新人可以从 MAP.md 快速理解全局
- 每个模块的行为契约在 domain 层文档中明确定义
- 端到端流程在 flows 层文档中可追踪
- 校验报告记录文档与代码的一致性状态

### 3.4 风控的多层防护

```
仓位层面：SL/TP自动触发 → 止损以触发价执行（非开盘价，避免滑点放大）
账户层面：杠杆率检查 → 超过清算线自动平仓
执行层面：限价单定价限制 → 成交概率低于阈值时回退市价单
系统层面：funding cost → 持仓时间越长成本越高，抑制过度持仓
```

## 四、核心机制原理

### 4.1 GARCH 价格区间预测

原理：金融资产波动率有聚类效应——大波动后面往往跟着大波动。GARCH(1,1) 用三个参数建模这个现象：

```
sigma_sq(t) = omega + alpha * epsilon_sq(t-1) + beta * sigma_sq(t-1)
```

- `omega`：长期平均方差
- `alpha`：上期冲击的敏感度
- `beta`：上期方差的持续性
- 约束：`alpha + beta < 1` 保证平稳性

预测区间 = `close +/- K * sigma`，K 值由基础值 + 因子调整 + miss_streak应急三重机制动态调整。

### 4.2 限价单生命周期

```
created → pending → [filled | cancelled | expired]
```

每bar的检查逻辑：
1. **成交检查**：bar_low <= 买单价 或 bar_high >= 卖单价 → 成交
2. **信号反转检查**：新信号方向与订单方向相反 → 撤单
3. **超时检查**：等待bar数 > max_wait → 过期
4. **预测过期检查**：预测区间不再包含当前价格 → 过期

### 4.3 决策管线的bar处理流程

每个bar经过 `DecisionPipeline` 的处理顺序（顺序很重要，决定优先级）：

```
observe(上一bar的预测 vs 实际) → predict(新预测)
  → manage_orders(检查限价单状态)
  → check_sl_tp(优先级最高，触发后跳过后续)
  → execute_pending(执行上一bar的决策)
  → evaluate_signals(根据信号决定下一步行动)
```

SL/TP 检查优先于信号评估——即使有新入场信号，如果当前bar触发了止损，先平仓，入场决策推迟到下一bar。

### 4.4 长时任务的可靠性保障

进化任务和模拟盘交易都是长时运行任务，系统通过：
- **守护线程**：后台运行，不阻塞主线程
- **状态机**：明确的任务状态转换（pending → running → completed/failed）
- **崩溃恢复**：持久化任务状态到数据库，重启后可恢复

## 五、总结

MyQuant 的设计哲学是**把交易决策的每个环节都变成可量化、可验证、可优化的工程问题**。策略不是"写代码"，是"编码基因"；回测不是"跑一遍"，是"bar-by-bar模拟真实执行环境"；进化不是"调参数"，是"搜索策略空间"。每一层都有明确的输入输出契约和独立的验证机制，层与层之间通过 `StrategyDNA` 这个统一的数据结构串联，形成从数据到决策的完整闭环。
