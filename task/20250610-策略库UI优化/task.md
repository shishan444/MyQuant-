# 策略库页面 UI 优化

## 任务目标
从 UI 设计视角和产品使用交互视角优化策略库页面（Strategies），使其更简单易用、更有效率。
核心关注：策略排序逻辑、星级展示、过滤交互、信息密度。

## 初始理解
- 策略库已有星级评分系统（verify_star 1-5 星）
- 当前已实现按星级降序排序、星级过滤
- 用户认为仍有优化空间，需要从产品视角深度审视

---

## 研究第 1 轮

### 任务结构性理解

策略库页面（Strategies.tsx）采用纯客户端渲染模式。后端一次拉取最多 200 条策略（固定 `created_at DESC`），前端通过 `useMemo` 做排序和过滤。页面结构为工具栏 → 表格（11列）→ 展开面板。

**核心诊断：信息层级扁平化。** 页面有 11 列数据，星级被嵌在名称列的小 badge 里（`Strategies.tsx:430-448`），"达标圆点"是一个 1.5px 的点（`Strategies.tsx:408-416`），两者都无法成为视觉焦点。用户打开策略库首先想知道"我有哪些好策略"，但当前设计让所有信息看起来同等重要，星级这个核心质量指标被淹没了。

**具体问题清单（附代码证据）：**

1. **星级嵌在名称列 badge 里** — `Strategies.tsx:430-448`，5个★字符+验证次数，在名称列内占位大但视觉权重低
2. **达标圆点几乎不可见** — `Strategies.tsx:408-416`，1.5px 圆点，用户很难注意到
3. **名称列排序语义错配** — `Strategies.tsx:889`，点击"名称"列头排的是 `verify_star`，用户预期按名称排序
4. **排序三态不直观** — `Strategies.tsx:723-729`，desc→asc→null 三态循环，第三态（取消排序）用户难以理解
5. **名称列信息过载** — `Strategies.tsx:420-449`，一行内塞了展开箭头+名称+来源badge+达标标签+星级badge，视觉噪音大
6. **服务端排序浪费** — `Strategies.tsx:659` 请求 `sort_by: "created_at"` 但前端立刻按 `verify_star` 重排

### 任务认知变化

研究前认为任务是"确认星级排序+小幅优化"。研究后发现核心问题是**信息层级重构**：星级应该是页面的第一视觉锚点，但目前它被嵌在名称列的次级 badge 里，和来源、达标标签混在一起，没有独立的视觉焦点。

这不是"加功能"的问题，是"组织方式"的问题。当前 11 列的表格把所有信息铺在同一层级，用户需要逐行扫描才能区分好策略和普通策略。

### 待消解的不确定性

无。所有关键判断都有代码证据支撑，且不确定性（策略数量级等）不影响核心设计方向。

### 决策
研究完成，进入推理链构建。

## 推理链

### 1. 任务定义

重构策略库页面的信息层级和功能交互：使星级评分成为独立醒目的视觉焦点，扩展过滤能力支持达标/不达标筛选，优化批量管理操作，让用户能高效识别优质策略并清理低质策略。

### 2. 现状定位

**问题类型：UI 设计问题（信息层级扁平化）**

策略库页面当前将星级评分嵌在名称列的 badge 中（`Strategies.tsx:430-448`），与来源 badge、达标标签、展开箭头挤在同一行（`Strategies.tsx:420-449`），视觉权重不足。同时存在一个独立的"达标圆点"列（`Strategies.tsx:408-416`，24px 宽），仅用一个 1.5px 的圆点表达达标/未达标状态，几乎不可见。

名称列点击排序的是 `verify_star` 而非名称（`Strategies.tsx:889`），语义错配。排序交互为三态循环 desc→asc→null（`Strategies.tsx:723-729`），第三态（取消排序）不符合常见交互模式。

核心问题：星级——策略最重要的质量指标——没有获得与重要性匹配的视觉层级。

**过滤维度缺失：** 当前验证过滤器（`Strategies.tsx:842-854`）只有 6 个选项（全部/已验证/未验证/3★+/4★+/5★），缺少"达标/不达标"过滤。用户无法快速筛选出不达标策略进行批量清理。批量操作仅支持"批量删除"（`Strategies.tsx:806-809`），功能单一。

### 3. 解决策略

**将星级从名称列 badge 提升为独立表格列**，替换当前的"达标圆点"列。

选择此策略的原因：
- 达标圆点列（24px）和星级 badge 表达的是同一件事（星级 > 0 等价于达标），合并消除冗余
- 独立列让星级成为行的第一个视觉锚点，用户扫视表格时左侧第一眼就是质量评级
- 改动范围可控——只改列布局和名称列内容，不改数据流和后端

排除的方案：
- 卡片式布局重写：工作量过大，偏离"简单优化"目标
- 服务端排序 verify_star：当前策略量级 <200，客户端排序足够，且后端 `_SORT_ALLOWED_COLUMNS` 不含 verify_star（`db_ext.py:1127-1131`），改动成本不值得

配套调整：
1. 名称列移除星级 badge 和达标标签（信息已由星级列表达）
2. 名称列排序改为按名称字母序
3. 排序交互改为两态循环（desc↔asc），移除 null 态
4. 扩展验证过滤器：新增"达标"和"不达标"选项，支持快速筛选低质策略
5. 优化批量操作区：增加"全选当前筛选"快捷操作

### 4. 范围边界

**改动文件：**
- `web/src/pages/Strategies.tsx` — 所有 UI 改动（列布局、星级列、名称列、排序逻辑）

**不改：**
- 后端 API / 数据库（`api/routes/strategies.py`, `api/db_ext.py`）— 数据和接口不变
- hooks / services 层（`useStrategies.ts`, `services/strategies.ts`）— 数据获取逻辑不变
- 类型定义（`types/api.ts`）— Strategy 类型的 verify_star 字段已存在
- 其他页面（Verify.tsx 等）

### 5. 行为规格

**5.1 星级列**
- 位置：表格第二列（紧跟 checkbox 后），替换原达标圆点列
- 宽度：48px
- 内容：
  - verify_star > 0 时：显示 `★{N}` 数字+星标，颜色按星级区分（5★=amber，3-4★=blue，1-2★=gray）
  - verify_star === 0 且 verify_count > 0 时：显示 `--`（灰色），表示已验证但未达标
  - verify_star 为 null（未验证）：显示空
- 排序：星级列可点击排序，默认降序，复合排序公式 `(verify_star ?? 0) * 10000 + (best_fitness ?? 0)`
- 不变量：星级列排序结果与当前 verify_star 排序公式一致（`Strategies.tsx:159`）
- 验证方式：`[代码审查]`

**5.2 名称列简化**
- 名称列移除星级 badge（`Strategies.tsx:430-448` 的星级展示代码删除）
- 名称列移除"达标"文本标签（`Strategies.tsx:427-429` 的达标标签代码删除）
- 名称列保留：展开箭头 + 策略名称 + 来源 badge
- 名称列排序：从 `verify_star` 改为按名称字母排序
- 排序公式新增 `name` accessor：`(s) => s.name ?? s.strategy_id`
- 不变量：名称列不再包含任何星级/达标信息，这些信息全部由星级列表达
- 验证方式：`[代码审查]`

**5.3 排序交互改为两态**
- cycleSort 函数改为 desc↔asc 两态循环，移除 null 第三态
- 点击已激活的 asc 状态 → 切回 desc（不是清除排序）
- 不变量：始终存在有效排序，不会出现无排序状态
- 验证方式：`[代码审查]`

**5.4 星级列加入 SORTABLE_COLUMNS**
- 星级列有独立的排序表头，与年化/回撤/胜率等并列
- 表头文字："星级"
- 不再在名称列表头处理星级排序
- 不变量：SORTABLE_COLUMNS 数组长度 +1，colgroup 和 colSpan 同步更新
- 验证方式：`[代码审查]`

**5.5 行左边框高亮调整**
- 当前达标行有 `border-l-2 border-l-emerald-400/30`（`Strategies.tsx:391`）
- 改为：星级 > 0 时显示金色左边框 `border-l-2 border-l-amber-400/20`，无星级时不显示
- 不变量：左边框颜色与星级颜色体系统一（amber 系列）
- 验证方式：`[代码审查]`

**5.6 过滤器扩展**
- 验证过滤器（verifyFilter）新增"达标"和"不达标"两个选项
- 过滤逻辑：
  - `qualified`：`strategy.qualified === true`（回测达标，无论是否验证过）
  - `unqualified`：`strategy.qualified === false`（回测未达标）
- 选项排列顺序：全部策略 → 达标 → 未达标 → 已验证 → 未验证 → 3★+ → 4★+ → 5★
- 不变量：新增选项不影响已有过滤逻辑，原有 6 个选项行为不变
- 验证方式：`[代码审查]`

**5.7 批量操作增强**
- 批量操作区保留"批量删除"按钮，新增"全选当前筛选"按钮
- "全选当前筛选"：点击后选中当前过滤+排序后的所有策略（sortedStrategies）
- 当已选数量等于当前筛选结果数量时，"全选"变为"取消全选"
- 不变量：批量操作只作用于用户可见的筛选结果，不包含被过滤掉的策略
- 验证方式：`[代码审查]`

### 6. 风险披露

**确定有风险：**
- 表格列结构变化（11列→10列，达标圆点列消失，新增星级列）→ 合并到 colgroup 和 colSpan 中 → 缓解：仔细同步所有 colgroup/colSpan 定义
- 名称列排序改为按名称字母序 → 用户可能习惯了点击名称按星级排序 → 缓解：星级列有自己的表头可点击，操作路径明确
- 过滤器选项增至 8 个 → 下拉菜单变长 → 缓解：选项按逻辑分组（全部→达标状态→验证状态→星级），顺序清晰

**不确定的风险：**
- 星级列 48px 宽度是否足够展示 `★5` 等内容 → 影响小，可在实现后微调

### 7. 实施顺序

1. **星级列替代达标圆点列** — 替换 colgroup 第二列、修改 StrategyRow 的达标圆点 td 为星级展示 td、新增星级列排序表头（高优先级，核心视觉锚点）
2. **名称列简化** — 移除星级 badge 和达标标签代码、新增 name 排序 accessor（依赖 1）
3. **排序交互修正** — cycleSort 两态化、名称列表头改按名称排序（依赖 2）
4. **过滤器扩展** — 新增达标/不达标过滤选项及逻辑（独立任务）
5. **批量操作增强** — 新增全选当前筛选按钮（依赖 4，过滤逻辑需先到位）
6. **行左边框颜色调整** — 达标→星级的颜色映射变更（独立任务）
