# 批量回测 UX 重设计

## 任务目标
从产品设计和用户交互视角重新设计批量回测页面，解决当前三个核心 UX 问题：
策略选择方式不友好、参数折叠无意义、结果呈现不够高效。

## 初始理解
- 当前策略选择是文本输入框（逗号分隔 ID），用户根本记不住策略 ID
- "高级参数"折叠区是伪设计——用户要么需要调参（那就不该折叠），要么不需要（那就不该存在）
- 结果展示用卡片列表，但比较效率不高
- Verify 页面已有策略列表加载能力（useStrategies hook），可复用

---

## 研究第 1 轮

### 任务结构性理解

**核心发现：BatchBacktest 的本质是"选择性深度回测"，与 Verify 的"全量验证"是不同工作流。**

- Verify（`Verify.tsx`）：加载全部策略 → 全量验证 → 产出星级/评分 → 筛选
- BatchBacktest（新设计）：从策略库精选策略 → 深度回测 → 查看权益曲线/交易信号

两者的用户心智模型不同：
- Verify：批量验证所有策略，找出优秀的（发现型）
- BatchBacktest：对已筛选的优秀策略做深度回测（确认型）

**三个 UX 问题的根因分析**：

1. **策略选择**：当前用文本输入框是因为后端 API 已就绪但前端偷懒。实际上 `useStrategies` hook 已提供策略列表加载，`Strategy` 类型包含 `strategy_id/name/symbol/timeframe/verify_star/source`，完全可以构建可视化选择器。

2. **参数折叠**：`init_cash`、`fee`、`slippage`、`leverage` 是回测的基本参数，不是"高级"参数。用户每次回测都可能调整初始资金和杠杆。Verify 页面把它们放在一行内联显示（`Verify.tsx:349-398`），这是正确的做法。

3. **结果呈现**：当前用 StrategySummaryCard 展示策略汇总，展开后是时段表格。问题在于：(a) 卡片视图不利于横向比较；(b) 展开二级（查看详情）嵌套过深。

**数据能力**：
- 前端已有 `useStrategies` hook 加载策略列表（含 verify_star）
- 后端 API `GET /api/strategies` 返回带 star 的策略列表
- Strategies 页面已有跳转入口（navigate with state.strategy_ids）
- SSE hook `useBatchBacktestStream` 已就绪
- 详情加载 `fetchBatchBacktestDetail` 已就绪

### 待消解的不确定性

无。所有前端能力已验证可用。

### 决策
研究完成，进入推理链构建。

## 推理链

### 1. 任务定义

重新设计批量回测页面的 UI 布局和交互流程，使策略选择直观高效、参数配置简洁直接、结果展示利于比较分析。

### 2. 现状定位

**问题类型：UX 设计缺陷（功能正确但交互不合理）**

三个问题的代码证据：
1. 策略选择：`BatchBacktest.tsx:57-62` 使用 `strategyIdsText` 文本输入 + 逗号分隔解析，用户需要手动输入 UUID
2. 参数折叠：`BatchBacktest.tsx:69-75` `advancedOpen` 状态控制折叠，`BatchBacktest.tsx:306-359` 整个折叠区需要额外点击才能看到参数
3. 结果展示：`BatchBacktest.tsx:534-660` 卡片嵌套表格嵌套详情，三层展开

对比 Verify 页面的正确做法：
- `Verify.tsx:349-398` 参数全部内联在一行，无折叠
- `Verify.tsx:141-143` 通过 `useStrategies` 加载策略列表
- `Verify.tsx:489-515` 结果用网格卡片展示，展开只有一层

**关键点**：后端 API 和数据流完全不需要改动，只改前端页面的 UI 组件和交互逻辑。

### 3. 解决策略

**三区垂直布局：配置区 → 进度区 → 结果区，策略选择器作为配置区的核心。**

设计原则：
1. **选择优于输入**：策略选择器从 API 加载列表，用 checkbox 多选，替代文本输入
2. **平铺优于折叠**：参数内联在配置栏，不设折叠区
3. **表格优于卡片**：结果用紧凑的表格行展示，便于横向比较；展开详情只一层

**策略选择器设计**：
- 从 API 加载策略列表（复用 `useStrategies` hook）
- 默认按星级降序排列，显示：checkbox、策略名、symbol/timeframe、星级、来源
- 顶部筛选栏：星级过滤（全部/≥4星/≥3星）、达标过滤、搜索
- 支持全选/清空操作
- 读取 `location.state.strategy_ids` 预选从策略库跳转的策略
- 底部显示已选数量

**参数设计**：
- 一行内联：资金、杠杆、费率、滑点
- 参照 Verify 的 `Verify.tsx:349-398` 布局
- 无折叠按钮，直接可见

**结果设计**：
- 汇总统计条：策略数、平均收益、达标率、最佳策略
- 策略列表用行式布局（非卡片），每行显示：名称、品种、星级、平均收益、fitness、达标率
- 点击行展开时段表格（一行展开，不是卡片展开）
- 时段表格中点击"详情"加载 equity curve + metrics

排除的方案：
- 左右分栏（策略选择器占左半屏）：页面宽度 1400px 不够舒适
- 弹窗选择器：增加操作步骤，不如内联直观
- 保持卡片布局：不利于多策略横向比较

### 4. 范围边界

**改动文件：**
- `web/src/pages/BatchBacktest.tsx` — 完全重写页面组件和子组件

**不改：**
- 后端 API — 所有端点和处理器不变
- `web/src/hooks/useStrategies.ts` — hook 已满足需求
- `web/src/services/strategies.ts` — SSE 和详情 API 已就绪
- `web/src/types/api.ts` — 类型已定义
- 其他页面 — 不影响

### 5. 行为规格

**5.1 策略选择器**
- 页面加载时通过 `useStrategies` 获取策略列表
- 策略按 verify_star 降序排列，星级为 null 的排最后
- 每条策略显示：checkbox、名称、symbol/timeframe、星级（星星图标）、来源标签
- 顶部筛选栏：全部/≥4星/≥3星（星级过滤）+ 全部/达标/未达标（达标过滤）
- 筛选后显示"全选当前"和"清空"按钮
- 支持 `location.state.strategy_ids` 预选
- 已选策略数量实时显示
- 无策略时显示空状态提示
- 验证方式：`[代码审查]`

**5.2 参数配置**
- 日期区间：预设快捷 + 自定义（复用现有逻辑）
- 参数一行内联：资金、杠杆、费率、滑点，参照 Verify 布局
- 无折叠区，所有参数直接可见
- 验证方式：`[代码审查]`

**5.3 启动控制**
- 至少选择 1 个策略 + 1 个有效日期区间才可启动
- 按钮显示已选策略数量："开始回测 (N 条策略)"
- 启动后配置区折叠为一行摘要（参照 Verify 的 configCollapsed 模式）
- 验证方式：`[代码审查]`

**5.4 进度展示**
- 保持现有 SSE 进度条设计
- 进度信息：当前步骤/总步骤、正在处理的 group、已完成数
- 取消按钮
- 验证方式：`[代码审查]`

**5.5 结果展示**
- 汇总统计条：策略数、平均收益、达标率
- 策略列表用行式布局，每行：名称、品种、星级、平均收益、fitness、达标率、展开按钮
- 排序：按 fitness 降序
- 点击行展开时段表格（每个时段一行：日期范围、收益、夏普、回撤、胜率、交易数、fitness、达标、查看详情按钮）
- 点击"查看详情"加载并显示 equity curve + BacktestMetricsPanel（复用现有逻辑）
- 验证方式：`[代码审查]`
