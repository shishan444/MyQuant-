# 日志与可观测性

## 涉及模块
| 模块 | 影响方式 |
|------|----------|
| logging | 日志基础设施，提供配置、格式化与工厂函数 |
| 所有 core 模块 | 通过 get_logger() 获取模块级 logger，输出结构化日志 |
| api | 使用 logging.getLogger("app") 记录请求与运行日志 |
| evolution | Runner 运行过程中记录进化进度与决策日志 |
| trading | Runner 运行过程中记录交易执行与状态变更日志 |

## 实现方式

项目基于 **Python 标准 logging 库** 构建日志体系，通过自定义配置与格式化器实现结构化、可追溯的日志输出。

### 日志配置

`core/logging/config.py` 负责日志环境的初始化配置。日志文件按模块分目录存储，路径规则为 `logs/{module}/{type}_{date}.log`，其中 `module` 为模块名称（如 evolution、trading），`type` 为日志类型（如 run、error），`date` 为当日日期。这种按模块和日期分割的策略，便于快速定位特定模块在特定时间段的运行记录，同时避免单个日志文件过大。

### 日志格式

`core/logging/formatter.py` 定义了自定义日志格式化器，输出格式为：

```
[TS] [TAG] [LEVEL] msg | context | file:line
```

各字段含义：
- **TS**：精确时间戳
- **TAG**：模块标签，标识日志来源
- **LEVEL**：日志级别（DEBUG / INFO / WARNING / ERROR）
- **msg**：日志主体消息
- **context**：上下文信息（如任务 ID、策略名称等结构化数据）
- **file:line**：源码文件名与行号，快速定位问题代码位置

### Logger 工厂

`get_logger()` 工厂函数是获取 Logger 的统一入口。调用时传入模块名，函数内部维护缓存字典，确保同名模块复用同一个 Logger 实例。这避免了重复创建 Handler 导致日志重复输出的问题。所有 core 模块通过此函数获取各自的 logger。

### API 层日志

API 层直接使用 `logging.getLogger("app")` 获取 logger，不经过 `get_logger()` 工厂。这与 core 模块的日志获取方式保持独立，API 请求日志与业务日志分离输出。

## 配置与约定
| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| 日志根目录 | `logs/` | 所有日志文件的根路径 |
| 日志文件路径 | `logs/{module}/{type}_{date}.log` | 按模块和日期分割 |
| 日志格式 | `[TS] [TAG] [LEVEL] msg \| context \| file:line` | 自定义格式化器输出 |
| Logger 获取方式 | `get_logger(module_name)` | core 模块统一使用工厂函数 |
| API Logger | `logging.getLogger("app")` | API 层独立获取，不经工厂函数 |
| Logger 缓存 | 按模块名缓存 | 同名模块复用 Logger 实例 |
