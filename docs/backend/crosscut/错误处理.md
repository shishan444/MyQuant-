# 错误处理

## 涉及模块
| 模块 | 影响方式 |
|------|----------|
| api | FastAPI 异常处理中枢，统一 HTTP 错误响应格式 |
| evolution | TaskStopRequested 协作式取消，进化过程中断控制 |
| trading | TaskStopRequested 协作式取消，实盘交易中断控制 |
| backtest | 策略参数校验（DNA 校验），回测前置检查 |

## 实现方式

项目采用 **分层校验 + 统一响应** 的错误处理策略，在数据入口、业务逻辑、运行控制三个层面分别拦截异常。

### API 层：请求校验与统一响应

FastAPI 框架内置的异常处理机制作为第一道防线。通过 `api/schemas.py` 中定义的 Pydantic V2 模型，所有 API 入参自动经过类型与约束校验。校验失败时，FastAPI 自动返回 **422 Unprocessable Entity** 响应，包含详细的字段级错误信息（字段名、错误类型、输入值）。

业务逻辑中的主动异常通过 `HTTPException` 抛出，FastAPI 将其转换为对应的 HTTP 状态码响应。所有 API 错误均采用统一的 JSON 响应格式，前端 `web/src/services/api.ts` 中对 422 错误有专门的解析逻辑，提取字段错误并映射到表单校验提示。

### 策略层：DNA 参数校验

`core/strategy/validator.py` 负责对进化生成的策略 DNA 进行校验。在回测执行前，验证策略参数的合法性（取值范围、类型、必填项等），避免无效参数进入回测引擎导致运行时错误。校验不通过时抛出明确的异常信息，标明具体参数与违规原因。

### 运行控制：协作式取消

进化模块和交易模块均定义了 `TaskStopRequested` 异常，用于实现协作式任务取消。当用户通过 API 请求停止某个运行中的任务时，对应 Runner 不会暴力终止线程，而是在下一个检查点主动抛出 `TaskStopRequested`，由上层捕获后执行资源释放与状态清理。这确保了进化过程中的中间数据和交易过程中的订单状态不会因中断而损坏。

- `api/runner.py` 中的进化 Runner 使用此机制响应用户的停止请求
- `core/trading/runner.py` 中的交易 Runner 使用此机制确保交易中断时订单安全

## 配置与约定
| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| HTTP 422 响应格式 | FastAPI 默认 | Pydantic V2 自动校验，含 detail 字段 |
| TaskStopRequested | 协作式取消 | 不强制终止，等待下一个检查点 |
| DNA 校验时机 | 回测执行前 | validator.py 在回测前拦截无效参数 |

## 源码锚点
- [→ api/schemas.py] Pydantic V2 请求模型定义，自动 422 校验
- [→ core/strategy/validator.py] 策略 DNA 参数校验逻辑
- [→ api/runner.py] TaskStopRequested 异常定义与进化任务取消处理
- [→ core/trading/runner.py] TaskStopRequested 异常定义与交易任务取消处理
- [→ web/src/services/api.ts] 前端 422 错误解析与表单提示映射
