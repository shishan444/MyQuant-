# 数据库与存储

## 涉及模块
| 模块 | 影响方式 |
|------|----------|
| persistence | 核心 DB 封装层，提供 SQLite CRUD 与连接管理 |
| data | Parquet 文件读写，K 线数据的持久化与加载 |
| api | 通过 db_ext 初始化扩展数据库，挂载 db_path / data_dir 配置 |
| evolution | 独立 evolution.db，存储进化任务、世代快照与进化历史 |
| trading | 独立 trading.db，记录实盘交易状态与订单数据 |

## 实现方式

项目采用 **SQLite + Parquet 混合存储**策略，将结构化元数据与非结构化时序数据分别存储，兼顾查询灵活性与读写性能。

### SQLite 存储

主数据库 `data/quant.db` 通过 `core/persistence/db.py` 提供统一的 CRUD 接口。数据库使用 **WAL（Write-Ahead Logging）模式**，允许读写并发，避免回测或进化过程中因写锁阻塞 API 读取。

扩展数据库的初始化由 `api/db_ext.py` 的 `init_db_ext()` 函数完成，负责创建 `evolution_task`、`generation_snapshot`、`evolution_history` 三张核心表，并管理 `data/evolution.db` 和 `data/trading.db` 两个独立数据库文件。表结构与索引通过 `migrations/` 目录下的 SQL 迁移文件按版本管理，当前共 6 个迁移脚本。

### Parquet 存储

K 线（OHLCV）数据以 Parquet 列式格式存储于 `data/market/` 目录下，文件命名规则为 `{交易对}_{周期}.parquet`（如 `BTCUSDT_1h.parquet`）。Parquet 格式具有高压缩比和列裁剪能力，适合存储大量历史行情数据。读写操作由 `core/data/storage.py` 封装，上层模块通过 Data 层接口访问，无需关心底层文件格式。

### 数据库迁移

`migrations/` 目录包含 6 个 SQL 文件，按序号执行。迁移脚本用于建表、加索引、修改字段等 schema 变更。初始化时由 `init_db_ext()` 依次执行未应用的迁移。

## 配置与约定
| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| data_dir | `data` | 数据根目录，config.yaml 中配置 |
| quant.db 路径 | `{data_dir}/quant.db` | 主数据库文件 |
| evolution.db 路径 | `{data_dir}/evolution.db` | 进化模块专用数据库 |
| trading.db 路径 | `{data_dir}/trading.db` | 交易模块专用数据库 |
| market 数据路径 | `{data_dir}/market/` | Parquet 文件存储目录 |
| journal_mode | `WAL` | SQLite 日志模式，启用并发读写 |
| Parquet 命名 | `{symbol}_{timeframe}.parquet` | K 线数据文件命名规则 |
| 迁移脚本 | `migrations/*.sql` | 按文件名序号顺序执行 |
