# 数据层

## 职责与边界

**负责**：
- 行情数据获取（币安公共数据 API K 线数据）
- 衍生品数据获取（持仓量 Open Interest / 资金费率 Funding Rate）
- Parquet 格式本地存储与增量更新
- CSV 文件导入（币安官方格式 / 通用 OHLCV 格式）
- 衍生品数据合并到 OHLCV（前向填充对齐）
- 多时间周期数据加载与指标预计算

**不负责**：
- 指标计算（由 features 模块负责，本模块在 mtf_loader 中调用）
- 策略信号生成（由 strategy 模块负责）

**边界**：本模块是系统与外部数据源的唯一交互层。上游（evolution runner / API）通过本模块加载和更新数据，下游模块始终通过本模块提供的 DataFrame 进行操作。

## 业务规则与不变量

1. **增量更新逻辑**：检查本地 Parquet 最新时间戳，仅拉取增量部分；无本地文件时执行全量拉取
2. **数据去重**：合并时 `duplicated(keep="last")` 保留最新值，排序后存储
3. **代理访问**：通过 BINANCE_PROXY 环境变量配置代理，默认 http://172.20.112.1:10809
4. **公共数据 API**：使用 data-api.binance.vision 而非标准 API，绕过区域限制
5. **CSV 精度检测**：自动检测时间戳为毫秒或微秒级
6. **衍生品前向填充**：OI / Funding Rate 与 OHLCV 对齐时使用 reindex + ffill，低频数据自然填充到高频 bar
7. **数据验证**：load_and_prepare_df 要求至少 min_bars=50 根 K 线才返回有效数据

## 设计意图

数据层采用"获取-存储-合并"三层架构。fetcher 负责与外部 API 交互，storage 负责 Parquet 持久化，updater 编排增量更新逻辑。这种分层使得每个职责可独立测试。

CSV 导入模块支持两种格式，满足用户导入币安官方历史数据和通用格式数据的需求。衍生品数据（OI / Funding Rate）独立获取后通过 derivatives_merger 前向填充合并到 OHLCV，使得衍生品指标可以在同一个 DataFrame 中计算。

mtf_loader 是数据层与特征工程层的桥梁：加载数据后立即调用 compute_all_indicators 预计算所有指标，返回可直接用于回测的增强 DataFrame。
