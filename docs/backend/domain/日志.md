# 日志 (logging)

## 职责与边界
**负责**：
- 按模块和日期组织日志文件路径
- AI 友好的日志格式化：结构化、可解析、可溯源
- 带 tag 的 Logger 工厂函数（缓存复用）
- 全局日志配置（级别、输出目标）

**不负责**：
- 业务日志的语义内容（由各模块自行决定记录什么）
- 日志文件的归档与清理（需外部 cron 或运维处理）
- 远程日志收集（无 syslog / ELK 集成）

**边界**：仅依赖 Python 标准库 logging 模块，零外部依赖。日志文件写入项目 logs/ 目录，按模块分子目录。

## 设计意图
日志模块的设计目标是"AI 友好"——格式化的日志既要人类可读，又要让 LLM 能快速解析关键信息。AIFormatter 的输出格式 `[时间] [标签] [级别] 消息 | 上下文 | 文件:行号` 遵循以下原则：(1) 方括号包裹的结构化字段便于正则提取；(2) `|` 分隔符让各字段边界清晰；(3) 结尾的 `file:line` 让 AI 能直接定位源码位置。

get_logger 工厂函数使用缓存机制确保同一个 tag 始终返回同一个 Logger 实例，避免重复添加 Handler 导致日志重复输出。

## 接口与契约

### 对外暴露的接口
| 接口 | 类型 | 签名 | 说明 |
|------|------|------|------|
| get_logger | 函数 | `(tag: str) -> Logger` | 获取/创建带 AI 格式化的 Logger（缓存复用） |
| get_log_path | 函数 | `(module: str, log_type: str) -> Path` | 按模块和日期生成日志文件路径 |
| configure_logging | 函数 | `(level, log_to_file) -> None` | 配置全局根 Logger |
| AIFormatter | 类 | `logging.Formatter` 子类 | AI 友好的日志格式化器 |

### 对外暴露的数据结构
| 数据结构 | 类型 | 用途 |
|-----------|------|------|
| AIFormatter | class | 自定义 Formatter，输出格式：`[TS] [TAG] [LEVEL] msg | context | file:line` |

## 模块依赖
| 依赖模块 | 依赖原因 |
|----------|----------|
| 标准库 (logging, pathlib, datetime) | 无外部依赖 |

## 业务规则与不变量
- 日志文件路径格式：`logs/{module}/{log_type}_{YYYYMMDD}.log`
- AIFormatter 输出格式：`[2026-04-11 15:30:00] [TAG] [LEVEL] msg | context | file:line`
- context 通过 `extra={"context": ...}` 传入，支持 dict 或字符串
- Logger 不向根 Logger 传播（`propagate = False`），避免重复输出
- 每个 Logger 绑定两个 Handler：控制台（DEBUG 级别）+ 文件（INFO 级别）
- 文件 Handler 自动创建父目录（`mkdir(parents=True, exist_ok=True)`）
