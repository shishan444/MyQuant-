# 模拟交易 (trading)

## 职责与边界
**负责**：
- 定义交易类型系统：Decision、AccountState、BarSignals、JudgmentConfig
- 纯判断规则引擎：基于信号和账户状态生成交易决策
- 虚拟账户管理：K 线开盘价执行、止损止盈、杠杆、资金费率、滑点
- 仓位状态机：持仓开/关/加/减的纯 Python 实现
- 后台运行器：守护线程执行模拟交易任务，含崩溃恢复

**不负责**：
- 策略信号计算（由 strategy/executor 承担）
- 历史数据获取（由 data/updater 承担）
- 回测引擎（由 backtest/engine 承担，回测使用 vectorbt）

**边界**：接收策略 DNA 和市场数据，输出模拟交易执行记录和权益快照。与回测引擎独立，回测面向批量历史分析，模拟交易面向逐 K 线实时推进。

## 设计意图
模拟交易系统的核心设计是"信号->判断->决策->执行"四层分离。(1) 信号层由 strategy/executor 生成 entry/exit/add/reduce 布尔信号；(2) 判断层（judgment.py）是一组纯函数规则，综合信号、账户状态和配置参数输出 Decision；(3) 决策被延迟到下一根 K 线开盘价执行（process_bar_v2），这避免了使用当前 K 线信号在同一根 K 线收盘价执行的幻觉；(4) 执行层（VirtualAccount）处理止损止盈、爆仓、资金费率等真实市场摩擦。

这个设计使系统从回测引擎中独立出来——回测用 vectorbt 做高速批量计算，模拟交易用纯 Python 逐 K 线推进，两者共享 DNA 但不共享执行路径。

## 状态机

模拟交易任务状态流转：

```
待运行(pending) -> 运行中(running) -> 暂停(paused) / 已停止(stopped) / 错误(error)
```

- 暂停后可恢复，恢复时从 last_bar_time 做 minimal replay
- 崩溃恢复：启动时调用 recover_stale_trading_tasks 将残留 running 状态标记为 stopped

每根 K 线内部处理顺序（process_bar_v2）：

```
1. 止损止盈检查（使用 HIGH/LOW，执行价 OPEN）
2. 爆仓检查（杠杆 > 1）
3. 执行待定 Decision（OPEN 价）
4. 资金费率扣除
5. 权益快照记录
```

判断规则优先级（evaluate）：

```
Rule 0: max_hold_bars 安全阀（亏损持仓超时强制平仓）
Rule 1: exit/reduce 信号 + 有持仓 -> 检查最小持仓时间和最小盈亏比
Rule 4: entry 信号 + 反向持仓 -> 先平仓
Rule 2: entry 信号 + 无持仓 -> 开仓（initial_entry_pct 比例入场）
Rule 3: entry 信号 + 同向持仓 -> 加仓（仅盈利时）
Rule 5: 无信号 -> 盈利且未达目标仓位时继续填充（受 max_fill_bars 限制）
```
