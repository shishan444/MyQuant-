# 回测引擎

## 职责与边界

**负责**：
- 基于 vectorbt 的 `from_order_func` 接口执行策略回测
- 实时止损止盈判断（基于 K 线 HIGH/LOW，非收盘价）
- 杠杆效果放大（equity curve 后处理）
- 杠杆资金费率扣除（仅持仓期间计费）
- 强制清算检测与处理
- 批量回测（种群级单次 vectorbt 调用）

**不负责**：
- 信号计算（由 strategy/executor 提供）
- 指标计算（由 features 模块提供）
- 评分（由 scoring 模块提供）

**边界**：本模块接受 StrategyDNA + 增强行情数据（已计算指标），输出 BacktestResult。是进化循环中"评估"环节的核心执行器，不涉及任何进化逻辑。

## 业务规则与不变量

1. **信号延迟**：所有信号 shift(1) 防止前瞻偏差，在 _build_portfolio 内统一处理
2. **止损止盈使用 HIGH/LOW**：多头止损判断 bar_low <= sl_level，止盈判断 bar_high >= tp_level；空头相反
3. **杠杆效果后处理**：vectorbt 以无杠杆模式运行，杠杆效果通过 _apply_leverage_to_equity 在 equity curve 上后处理放大
4. **资金费率仅持仓期间扣除**：通过 trades_df 的 Entry/Exit Timestamp 构建持仓掩码，非持仓 bar 不扣费
5. **清算检测**：杠杆 > 1 时，当价值低于 maintenance margin 触发强制平仓
6. **清算后可重入**：清算后如有入场信号且资金充足，允许重新开仓
7. **批量回测行列对应**：N 个个体的信号堆叠为 (N, M) 矩阵，每个个体对应一列，参数以 per-column 数组传入

## 设计意图

回测引擎选择 vectorbt 的 `from_order_func` 而非预设信号模式，是为了实现逐 bar 的自定义订单逻辑 -- 止损止盈、加仓减仓、杠杆清算等都需要在订单层面实时判断。Numba JIT 编译的 `order_func_nb` 确保了逐 bar 循环的性能。

批量回测是性能关键路径：通过将种群所有个体的信号堆叠为 (N, M) 矩阵，单次 `Portfolio.from_order_func` 调用即可完成整个种群的评估，避免了 N 次独立回测的开销。信号计算的 batch_signal_sets 进一步通过基因签名去重，避免重复计算相同指标条件。
