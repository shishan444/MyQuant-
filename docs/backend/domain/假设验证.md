# 假设验证 (validation)

## 职责与边界
**负责**：
- WHEN/THEN 假设验证：给定一组触发条件和结果条件，在历史数据上统计命中率
- 入场/出场规则评估：按规则配对买卖信号，计算胜率、收益率等交易统计
- 多时间周期数据加载与合并（防前瞻偏差的 forward-fill 对齐）
- 技术形态检测（顶底背离、连续涨跌、触价反弹、角色反转）
- 场景验证：6 种独立场景检测器 + 前瞻统计分析

**不负责**：
- 策略进化与 DNA 编码（由 evolution/ 承担）
- 实盘/模拟交易执行（由 trading/ 承担）
- 指标计算本身（委托给 features/indicators）

**边界**：接收原始 OHLCV 数据 + 用户定义的条件/参数，输出结构化验证结果。所有检测器无状态，纯函数式设计。

## 设计意图
假设验证模块是连接"人类直觉"和"数据真相"的桥梁。交易者经常有"当 RSI 超卖后价格大概率反弹"这样的假设，但缺乏系统化的验证手段。本模块提供两种验证路径：(1) WHEN/THEN 验证适合"如果满足条件 X，则未来 N 根 K 线内会发生 Y"这类假设；(2) 场景验证适合"双顶形态出现后价格平均怎么走"这类更复杂的模式分析。两者都内置多时间周期支持，避免因视角单一导致误判。

### 对外暴露的数据结构
| 数据结构 | 类型 | 用途 |
|-----------|------|------|
| ValidationResult | dataclass | 假设验证完整输出：命中率、触发记录、分布、百分位、信号频率 |
| TriggerRecord | dataclass | 单次触发事件：时间、价格、变化率、指标快照 |
| DistributionBucket | dataclass | 直方图桶：区间范围、命中/未命中计数 |
| RuleResult | dataclass | 规则评估输出：买卖信号、交易记录、胜率、总收益 |
| RuleSignal | dataclass | 单个买卖信号：时间、价格、类型 |
| TradeRecord | dataclass | 完整交易记录：入场/出场时间价格、收益率、胜负 |
| SceneVerificationResult | dataclass | 场景验证输出：触发点列表、按前瞻周期聚合的统计 |
| TriggerPoint | dataclass | 场景触发点：时间、价格、指标快照、子类型 |
| HorizonStats | dataclass | 单触发点的前瞻统计：收益率、最大回撤、到峰/谷 K 线数 |
| AggregateStats | dataclass | 多触发点聚合统计：胜率、平均收益、分布 |
| SceneDetector | ABC | 场景检测器抽象基类：name / default_params / detect |

## 业务规则与不变量
- 条件评估支持 AND/OR 逻辑组合，每条条件独立指定逻辑运算符
- action 类型映射：touch / cross_above / cross_below / gt / lt / ge / le / spike / shrink / divergence_top / divergence_bottom / consecutive_up / consecutive_down / touch_bounce / role_reversal / cross_above_series / cross_below_series / lookback_any
- 多时间周期合并时，高周期时间戳向前偏移一个 base_tf 单位以防止前瞻偏差
- 场景检测器 6 种：top_pattern、volume_spike、mean_reversion、volume_breakout、support_resistance、cross_timeframe
- top_pattern 含 3 个子类型（double_top / head_shoulders_top / triple_top），通过 SUB_PATTERN_PARENT 映射
- THEN 条件每个可有独立 window，评估时使用最大 window 截取前瞻区间
