# 错误处理

## 涉及模块
| 模块 | 影响方式 |
|------|----------|
| pages | 每个路由页面被 ErrorBoundary 包裹，渲染崩溃时展示降级 UI 并提供重试入口 |
| services | api.ts Axios 响应拦截器统一拦截后端错误，将 Pydantic 422 校验错误、网络异常、超时等转换为可读 message |
| components | ErrorBoundary 组件作为 class component 捕获子树渲染异常 |
| hooks | 每个 useMutation 内置 onSuccess / onError 回调，通过 sonner toast 向用户反馈操作结果 |

## 实现方式

整体采用"三层拦截"策略，从网络层到渲染层逐级兜底：

**第一层：Axios 响应拦截器 (services/api.ts)**
- 所有 API 请求经过统一的 `api.interceptors.response` 拦截器处理
- Pydantic 422 校验错误：自动解析 `detail` 数组，提取 `loc` 和 `msg` 字段拼接为可读消息（如 `symbol: field required; timeframe: not a valid value`）
- 字符串类型 `detail`：直接透传后端返回的错误消息
- 其他情况（网络断开、超时等）：回退到 `error.message` 或默认文案 "请求失败"
- 最终统一 `reject(new Error(message))`，确保下游拿到的都是标准 Error 对象

**第二层：React ErrorBoundary (components/ErrorBoundary.tsx)**
- 每个 `/lab`、`/evolution`、`/strategies`、`/trading`、`/data`、`/settings` 路由页面均被 ErrorBoundary 包裹
- 使用 `getDerivedStateFromError` 捕获子组件树中未处理的渲染异常
- 降级 UI 展示错误图标、错误消息文本和 Retry 按钮
- Retry 通过递增 `retryKey` 强制重新挂载子树，实现无刷新重试
- 支持自定义 `fallback` 属性覆盖默认降级 UI

**第三层：Mutation 级 toast 反馈 (hooks/\*)**
- 所有 useMutation 统一配备 `onSuccess`（绿色 toast）和 `onError`（红色 toast）回调
- 成功消息简洁明确，如 "Task created"、"策略已保存"
- 失败消息携带具体原因：`创建失败: ${err.message}`
- 使用 sonner 库渲染 toast，轻量且不阻断用户操作流

**超时控制**
- Axios 实例全局设置 `timeout: 30000`（30 秒），超时后自动触发 error 回调

## 配置与约定
| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| axios timeout | 30000ms | 单次请求最大等待时间 |
| ErrorBoundary retryKey | 0 | 点击 Retry 自增，触发子树重新挂载 |
| sonner toast duration | 默认（约 4s） | 部分 error toast 设置 `duration: Infinity` 需手动关闭 |
| Pydantic 422 解析 | loc.slice(1).join(".") | 去掉 body 前缀，只展示字段路径 |
