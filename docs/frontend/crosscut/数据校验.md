# 数据校验

## 涉及模块
| 模块 | 影响方式 |
|------|----------|
| services | api.ts 响应拦截器自动解析后端 Pydantic 422 校验错误，转换为前端可读消息 |
| components | 表单组件使用 react-hook-form + zod schema 进行客户端即时校验 |
| types | types/api.ts 定义完整的 TypeScript 接口，编译期静态检查保证类型安全 |
| hooks | useMutation 内的 onError 回调接收解析后的校验错误消息，通过 toast 展示 |

## 实现方式

项目采用前后端双重校验策略，既保证用户体验（前端即时反馈），又保证数据一致性（后端强制校验）。

**后端校验：Pydantic V2 + FastAPI**
- FastAPI 路由函数通过 Pydantic BaseModel 自动校验请求体，类型不匹配或字段缺失时返回 422 Unprocessable Entity
- 响应体格式为 `{ detail: [{ loc: ["body", "field_name"], msg: "error description", type: "value_error" }] }`
- 前端 api.ts 拦截器在响应错误分支中检测 `detail` 字段：如果是数组则按 Pydantic 格式解析，拼接为 `"field: message"` 格式的可读字符串

**前端校验：Zod + react-hook-form**
- 使用 `zod`（v4.x）定义表单校验 schema，与 TypeScript 类型系统深度集成
- 通过 `@hookform/resolvers` 将 Zod schema 桥接到 react-hook-form 的 `resolver` 配置
- 表单提交前在客户端完成即时校验，字段级错误消息直接展示在对应输入框旁
- 校验通过后才会发起 API 请求，减少无效网络调用

**TypeScript 静态类型检查**
- 项目启用 TypeScript strict mode，编译期捕获类型不匹配
- `types/api.ts` 集中定义所有后端交互接口（约 418 行），涵盖：DNA、Strategy、EvolutionTask、Dataset、BacktestResult、ValidateRequest/Response 等全部数据结构
- 前端接口与后端 `api/schemas.py` 保持人工同步，变更时需双侧同步更新

**校验错误流转路径**
1. 用户提交表单 -> react-hook-form 调用 Zod schema 校验 -> 校验失败时在表单内展示字段级错误
2. 校验通过 -> API 请求发出 -> 后端 Pydantic 再次校验 -> 若 422 则返回 detail 数组
3. api.ts 拦截器解析 422 detail -> 拼接可读消息 -> `reject(new Error(message))`
4. useMutation 的 onError 回调接收 Error -> sonner toast 展示错误消息给用户

## 配置与约定
| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| zod 版本 | ^4.3.6 | Zod v4，用于前端表单 schema 定义 |
| react-hook-form 版本 | ^7.72.1 | 表单状态管理 |
| @hookform/resolvers | ^5.2.2 | Zod schema 到 react-hook-form resolver 的桥接 |
| TypeScript strict mode | 启用 | tsconfig 中启用严格模式 |
| 422 解析策略 | loc.slice(1).join(".") | 去掉 loc 数组第一个 "body" 元素，拼接剩余路径 |
| types 集中管理 | types/api.ts | 所有后端交互接口定义在单一文件中 |
