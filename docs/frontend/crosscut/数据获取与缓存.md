# 数据获取与缓存

## 涉及模块
| 模块 | 影响方式 |
|------|----------|
| hooks | 所有 hooks 文件定义 query key factory、queryOptions、useMutation，是数据获取的核心入口 |
| services | 纯函数层，每个 service 函数封装一个 Axios 调用，供 hooks 的 queryFn 使用 |
| pages | 页面组件通过调用 hooks（如 useEvolutionTasks、useTradingTasks）获取数据，不直接操作 QueryClient |
| components | 子组件接收 props 或通过 hooks 获取局部数据，如 OHLCV 图表数据 |

## 实现方式

**TanStack React Query v5 作为服务端状态管理核心**

整个前端不使用 Redux 或 Zustand 管理服务端数据，而是将 TanStack React Query 作为唯一的服务端状态源。所有 API 数据的获取、缓存、失效、轮询均由 React Query 统一调度。

**QueryClient 全局配置 (App.tsx)**
- `staleTime: 30000` -- 数据在 30 秒内被视为新鲜，不会自动重新请求
- `retry: 1` -- 请求失败后仅重试 1 次，避免长时间等待
- `refetchOnWindowFocus` 保持默认（true），用户切回标签页时自动刷新已过期数据

**Query Key Factory 模式**

每个服务领域维护一个 keys 对象，通过层级化 key 管理缓存粒度：

| 领域 | keys 对象 | 文件 |
|------|-----------|------|
| 进化 | evolutionKeys | useEvolution.ts |
| 交易 | tradingKeys | useTrading.ts |
| 策略 | strategiesKeys | useStrategies.ts |
| 数据集 | datasetsKeys | useDatasets.ts |
| 图表 | chartKeys | queries/chartQueries.ts |

key 按层级设计：`all -> list(filters) / detail(id) -> 子资源(id)`。invalidate 时可以按粒度精确失效：`strategiesKeys.all` 失效全部策略数据，`strategiesKeys.detail(id)` 只失效单个策略。

**queryOptions 函数化封装**

每个查询导出 `queryOptions()` 函数（如 `evolutionTasksOptions()`、`tradingTaskOptions(taskId)`），将 `queryKey`、`queryFn`、`enabled`、`refetchInterval` 等配置收敛到一处。页面组件通过 `useQuery(xxxOptions())` 调用，实现声明式数据获取。

**useMutation 自动缓存失效**

所有写操作（创建、停止、暂停、恢复、删除等）使用 `useMutation`，在 `onSuccess` 回调中通过 `qc.invalidateQueries()` 精准失效相关 query。例如：
- 创建进化任务：失效 `["evolution", "tasks"]`
- 停止进化任务：同时失效任务列表和单个任务详情
- 删除策略：失效 `strategiesKeys.all`（整个策略域）

**活跃任务自动轮询**

对于运行中的任务，通过 `refetchInterval` 实现条件轮询，任务完成后自动停止：
- 进化任务列表：`isActiveStatus(status)` 为 true 时每 10 秒轮询
- 单个进化任务：运行中每 5 秒轮询
- 进化历史：活跃时每 3 秒轮询
- 交易任务列表：有 running/pending 任务时每 5 秒轮询
- 单个交易任务：运行中每 3 秒轮询
- 交易 Runner 状态：固定每 10 秒轮询

`isActiveStatus()` 定义在 `lib/constants.ts`，判断 `status === "running" || status === "pending"`。

**WebSocket 实时更新**

进化模块和交易模块均通过 WebSocket 接收后端推送，实现秒级数据更新：

- **evolution WebSocket** (`useEvolutionWebSocket`)：连接 `/ws/evolution/{taskId}`，接收 `generation_complete`、`evolution_complete`、`phase_changed`、`population_started`、`strategy_discovered` 等事件。对于增量数据（如新一代完成），直接通过 `qc.setQueryData` 合并到缓存（如实时追加速化历史记录到图表），无需重新请求。任务完成后通过 `evolution_complete` 事件将 status 更新为 "completed"。

- **trading WebSocket** (`useTradingWebSocket`)：连接 `/ws/trading/{taskId}`，接收 `position_update`、`task_started` 事件。收到消息后延迟 2 秒批量 invalidate 相关 query（tasks、task、trades、equity、metrics），避免频繁请求。断线后 3 秒自动重连。

## 配置与约定
| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| staleTime | 30000ms | 全局默认，数据在 30s 内视为新鲜 |
| retry | 1 | 全局默认，失败后仅重试 1 次 |
| refetchOnWindowFocus | true | 切回浏览器标签页时自动刷新过期数据 |
| ohlcv staleTime | 60000ms | OHLCV 和图表指标数据缓存 1 分钟（市场历史数据变化少） |
| availableSources staleTime | 300000ms | 可用数据源列表缓存 5 分钟 |
| 进化列表轮询 | 10000ms | 活跃任务自动轮询间隔 |
| 进化详情轮询 | 5000ms | 活跃单任务轮询间隔 |
| 进化历史轮询 | 3000ms | 活跃任务历史轮询间隔 |
| 交易列表轮询 | 5000ms | 有活跃任务时轮询间隔 |
| 交易详情轮询 | 3000ms | 运行中任务轮询间隔 |
| Runner 状态轮询 | 10000ms | 固定轮询间隔 |
| WebSocket 重连 | 3000ms | 断线后重连等待时间 |
| WS invalidation 延迟 | 2000ms | 收到推送后延迟批量 invalidate |
